#+TITLE: The editor
#+DESCRIPTION: How the editor displays org text, folds it, reports state in the modeline and echo area, completes, checks spelling, pairs brackets, wraps lines and undoes.
#+LEDE: The editor shows an org file as plain text with its markup styled or hidden, folds headings, drawers and blocks the way Org does, and reports position and state in a modeline and echo area below the text.

* What the editor shows

The editor holds the file's text exactly as it is on disk. Styling, hidden markup, indentation and images are display only; none of them change the file.

Org files open with the caret at the start of the file, as in Emacs. Buffers you had open when you quit reopen with the caret where you left it.

** Markup

View ▸ Show Markup (=⇧⌘M=; palette: Show or Hide Markup) is off by default. While it is off:

- Link brackets and targets are hidden, so =[[https://orgmode.org][Org]]= shows as an underlined =Org=, as with =org-link-descriptive=.
- Emphasis markers (the =*= of bold, the === of verbatim and so on) are hidden when =org-hide-emphasis-markers= is on, which is the default.
- Entities and sub- and superscripts are drawn as characters when =org-pretty-entities= is on, which is the default (see /Entities/ below).

The line with the caret always shows its markup, so you can edit it. Moving to another line hides it again. Turn Show Markup on to see all markup everywhere. The =config.toml= setting is =show-markup= in =[orgstar]=.

The two Org options are in Settings ▸ Editing as "Emacs hides emphasis markers" and "Emacs shows entities as characters", and in =config.toml= as =org-hide-emphasis-markers= and =org-pretty-entities=. They also tell orgstar how wide your Emacs displays text, so tag alignment, table alignment and =M-q= produce the same file Emacs would. Set them to match your Emacs.

** Styling

- Headings are bold and coloured by level (eight colours, as =org-level-1= to =org-level-8=). Levels 1 to 3 are larger than body text: each level is a step larger than the one below it, and level 4 and deeper are body size. The step is Settings ▸ Appearance ▸ "Headings grow by N pt a level" (1 pt by default, 0 to 8).
- TODO and DONE keywords are bold, in the TODO or DONE colour, or a colour you set for that keyword.
- Priorities, tags, timestamps, comments, keywords (=#+TITLE:= and the like), planning lines and drawers, block delimiters and tables each have a colour; footnotes, targets, macros and LaTeX share one.
- Bold, italic, underline and strike-through are drawn as such; verbatim and code get their own colour and background.
- Links are underlined.
- Blocks (=#+BEGIN_…= to =#+END_…=), dynamic blocks and fixed-width lines are drawn on a shaded band across the whole width of the editor, as Emacs extends the =org-block= face. Code in src blocks is highlighted for its language (see [[file:11-code-blocks.org][Code blocks]]).
- A folded heading shows an ellipsis after its line.

Colours come from the theme and follow the system's light or dark appearance. The font, size, line spacing and text width are in Settings ▸ Appearance; colours are set in =config.toml=. See [[file:13-configuration.org][Configuration]]. The font should be monospaced, since tags and tables line up by columns. A body font for prose can be set beside it, as =mixed-pitch-mode= does in Emacs: prose and headings use it, and tables, code, dates, tags, drawers and the start of each line keep the monospaced font.

** Adding emphasis

Emphasize… (=C-c C-x C-f= in the Emacs and Doom presets, =org-emphasize=) asks for a marker: =*= bold, =/= italic, =_= underline, === verbatim, =~= code, =+= strike-through, or =SPC= to remove emphasis. With a selection it wraps the selection in the marker, replacing one the selection already has. Without one it inserts a pair of markers with the caret between them. A space goes before or after the markers where the text next to them couldn't border emphasis, as Org adds it.

The Mac preset binds =⌘B=, =⌘I= and =⌘U= to bold, italic and underline. Each marker is also a command of its own in the palette (Bold, Italic, Underline, Verbatim, Code, Strike-Through), for binding in =keymap.toml=; see [[file:03-keys.org][Keys and commands]]. On iOS, Bold, Italic and Code are in the edit menu of a selection, under Format, and in Commands.

** Indentation and stars

Org files display as =org-indent-mode= shows them, by default: each heading's body is indented to start one column past its stars, all stars but the last are hidden, and a wrapped heading title continues under the title. The indentation is display only; the file keeps its text at the left margin.

Body lines that wrap continue under their own text: past leading spaces, and past a list item's bullet and checkbox, as =adaptive-wrap= does.

| Setting                                 | Default | What it does                                                         |
|-----------------------------------------+---------+----------------------------------------------------------------------|
| =org-startup-indented=                  | on      | Indent bodies under their headings. =#+STARTUP: indent= or =noindent= overrides it per file. |
| =org-hide-leading-stars=                | off     | Without indentation, show only a heading's last star. =#+STARTUP: hidestars= or =showstars= overrides it. |

With both off, headings show all their stars and bodies start at the left margin. Both settings are in =config.toml= only, and are read when a file opens.

** Entities

When =org-pretty-entities= is on and Show Markup is off:

- An entity such as =\alpha= or =\to= is drawn as its character (=α=, =→=), taking one column.
- =x_{1}= and =x^{2}= are drawn lowered and raised, without their markers. Braces are required: =x_1= is left as typed.

Entities are left as typed on the caret's line, in comment lines and inside blocks. Sub- and superscripts are left as typed inside emphasis, links and keywords.

** Inline images

Org ▸ Show or Hide Inline Images (=C-c C-x C-v= in the Emacs and Doom presets), as =org-toggle-inline-images= does, draws images in place of their links. The echo area reports how many images it displayed.

A =file:= or =attachment:= link to an image file shows as its image wherever the link is: on a line of its own, or in the text of a paragraph, a heading, a list item or a table:

#+BEGIN_SRC org
#+ATTR_ORG: :width 400
[[file:images/diagram.png]]

The plot [[file:images/plot.png]] and the photo file:images/photo.jpg share a line.

| Before | [[file:before.png]] |
| After  | [[file:after.png]]  |
#+END_SRC

- Recognised extensions: =png=, =jpg=, =jpeg=, =gif=, =svg=, =webp=, =tif=, =tiff=, =bmp=, =heic=, =avif=.
- Paths are relative to the file's folder; =~= is expanded. Images at http(s) links show when =org-display-remote-inline-images= is =download= or =cache=; see [[file:09-links.org::*Remote images][Remote images]].
- =attachment:= links, such as =[[attachment:photo.jpg]]=, show the file from the entry's attachment folder, found as following the link finds it: the =DIR= property, else the =ID= folder under =org-attach-id-dir=. See [[file:04-outlines.org][Outlines]] for attachments.
- A link with a description shows as a link, unless the description is itself one =file:= or =attachment:= link to an image, plain or in angle brackets: =[[https://example.com][file:thumbnail.png]]= shows =thumbnail.png=. Show or Hide Inline Images, Including Described Links (=C-u C-c C-x C-v= in the Emacs preset, and in the command palette), as =org-toggle-inline-images= with a prefix argument does, also shows the image a described link points to, such as =[[file:plot.png][the plot]]=; the link's path then decides, not its description.
- Links in verbatim and code text, comments, keyword lines, and source and example blocks stay text.
- =#+ATTR_ORG: :width N= above a paragraph sets the width in points of each image in it. Images are never wider than the editor.
- A link that is all its line holds shows its image on that line. An image in a line's text stands where its link is, and its line is as tall as the image.
- The link text is hidden while its image shows, except on the caret's line. There the image is drawn under the link, or under the paragraph for an image in a line's text.

To show images when a file opens, add =#+STARTUP: inlineimages= to the file, or set =org-startup-with-inline-images = true= in =config.toml=. =#+STARTUP: noinlineimages= turns it off for one file. Images shown when a file opens leave described links as links, as in Org.

** LaTeX previews

Show or Hide LaTeX Previews (=C-c C-x C-l= in the Emacs and Doom presets, and in the command palette) draws LaTeX fragments and environments as typeset math, as =org-latex-preview= does. The echo area reports how many fragments it previewed.

#+BEGIN_SRC org
The area is $\pi r^2$, and \(\sqrt{2}\) is irrational.
\begin{equation}
\int_0^1 x\,dx = \frac{1}{2}
\end{equation}
#+END_SRC

- =$…$= and =\(…\)= are typeset as inline math, =$$…$$=, =\[…\]= and environments as display math. =equation=, =align=, =gather= and their starred forms are typeset as their bodies, aligned or gathered.
- The math is typeset by orgstar itself, with the Latin Modern Math font, in the editor's text color and size; it needs no TeX installation and works on iOS. It reads the math commands LaTeX's =amsmath= has for formulas, not packages a file loads with =#+LATEX_HEADER=. A fragment it can't read stays as text.
- The caret's line shows the source, so you can edit it.
- Fragments in source and example blocks aren't previewed.

The command switches previews for the whole buffer; Org's =C-u= forms, which act on the section at point, aren't there. To preview when a file opens, add =#+STARTUP: latexpreview= to the file, or set =org-startup-with-latex-preview = true= in =config.toml=. =#+STARTUP: nolatexpreview= turns it off for one file. After switching between light and dark appearance, switch previews off and on to redraw them in the new color.

* Folding

Headings, drawers and blocks fold as in Org. Folding is display only and isn't saved in the file.

** Cycling

| Action                         | Emacs and Mac presets | Doom                                                 | Org command          |
|--------------------------------+-----------------------+------------------------------------------------------+----------------------|
| Cycle the heading or element at the caret | =TAB=      | =TAB= in normal and visual state                     | =org-cycle=          |
| Cycle the whole file           | =S-TAB=               | =S-TAB=, =z A= in normal state; =S-TAB= in visual state | =org-global-cycle=   |
| Open or fold the heading       |                       | =z a= in normal state                                | =+org/toggle-fold=   |
| Open the heading one level     |                       | =z o= in normal state                                | =+org/open-fold=     |
| Fold the subtree the caret is in |                     | =z c= in normal state                                | =outline-hide-subtree= |

The titles in the palette and the Org menu are Cycle Visibility, Cycle Global Visibility, Toggle Fold, Open Fold and Close Fold.

Toggle Fold and Open Fold act on a heading line: a folded heading opens one level, showing its body and its child headings, each folded. On an open heading, Toggle Fold folds it and Open Fold does nothing. Close Fold folds the subtree of the heading the caret is under, from anywhere in it.

=TAB= on a heading line cycles that heading: folded, then its children, then the whole subtree, then folded again. A heading without children goes straight from folded to open. =TAB= on the first or last line of a drawer or block folds or opens it; drawer and block folds are kept apart from heading folds, so cycling a heading leaves them as they are. Elsewhere =TAB= does what it otherwise would: in a table it moves to the next field, and in plain text it inserts a tab.

In Doom's insert state, =TAB= and =S-TAB= on a heading demote and promote it, and on a list item indent and outdent it, as Doom's =+org-indent-maybe-h= does. Use normal state to fold.

=S-TAB= cycles the whole file through three states, starting at the first:

1. Overview: top-level headings only.
2. Contents: every heading, no bodies.
3. Show all: everything, with blocks opened. Drawers stay folded.

Overview and contents also fold drawers before the first heading.

Clicking a heading's stars cycles that heading, as =TAB= does on it.

The caret can't rest in folded text: moving forward into a fold jumps past it, and moving back into one goes to the end of the heading line. Going to a location from the outline pane, search, a link or the agenda opens whatever folds hide it.

** Folding when a file opens

With no =#+STARTUP= visibility option, a file opens with every heading shown. Drawers start folded (=org-cycle-hide-drawer-startup=, on by default); blocks start open (=org-cycle-hide-block-startup=, off by default). Both settings are in =config.toml=.

=#+STARTUP= options a file can set:

| Option                                 | Effect when the file opens                                  |
|----------------------------------------+-------------------------------------------------------------|
| =overview=, =fold=                     | Top-level headings only                                     |
| =content=                              | Every heading, no bodies                                    |
| =showall=, =nofold=                    | Everything                                                  |
| =show2levels=, =show3levels=, …        | Headings down to that level, no bodies                      |
| =showeverything=                       | Everything, including drawers and blocks; =VISIBILITY= properties are ignored |
| =hidedrawers=, =nohidedrawers=         | Fold or open drawers                                        |
| =hideblocks=, =nohideblocks=           | Fold or open blocks                                         |
| =indent=, =noindent=                   | Indent bodies under headings, or not                        |
| =hidestars=, =showstars=               | Hide all stars but the last, or not                         |
| =inlineimages=, =noinlineimages=       | Show image links as images, or not                          |
| =latexpreview=, =nolatexpreview=       | Show LaTeX fragments as typeset math, or not                |
| =align=, =noalign=                     | Align every table, or not (=org-startup-align-all-tables=)  |
| =shrink=                               | Narrow table columns that have width cookies                |

#+BEGIN_SRC org
#+STARTUP: content hideblocks
#+END_SRC

When the file sets a visibility (=overview=, =content=, =showall=, =showNlevels= and the like, but not =showeverything=), orgstar then applies each heading's =VISIBILITY= property and folds subtrees tagged =ARCHIVE=, as =org-cycle-set-visibility-according-to-property= and =org-cycle-hide-archived-subtrees= do. =VISIBILITY= takes =folded=, =children=, =content= or =all=:

#+BEGIN_SRC org
,* Reference
:PROPERTIES:
:VISIBILITY: folded
:END:
#+END_SRC

=#+STARTUP= options are read from the file and from any =#+SETUPFILE= it names, and take effect when the file opens. To apply changed options to an open file, close its buffer and open it again.

Narrowing to a subtree or block, and sparse trees, also hide text; see [[file:04-outlines.org][Outlines]].

* Panes and windows

A window can show more than one buffer at once, or one buffer in more than one place, as Emacs windows do. Split Pane Below (=C-x 2=) and Split Pane Right (=C-x 3=) divide the pane with the focus in two; the new pane shows the same buffer, and the focus stays where it was. Drag the line between two panes to resize them. Close Pane (=C-x 0=) removes the focused pane, Close Other Panes (=C-x 1=) leaves only it, and Next Pane (=C-x o=) moves the focus through the panes in reading order. With several panes, a bar along the top marks the one with the focus. The sidebar, the outline and the title follow the focused pane. In the Doom preset these are =SPC w s=, =SPC w v=, =SPC w d=, =SPC w o= and =SPC w w=, and =C-w= with the same letters in normal state; the Mac preset and the View menu use =⌃⌘2=, =⌃⌘3=, =⌃⌘0=, =⌃⌘1= and =⌥⌘`=.

Each pane has its own caret, selection and scroll position, and its own tabs (see [[file:01-files-and-folders.org][Files and folders]]): the buffers it has shown. Everything else about a buffer is the buffer's, as in Emacs: its text and undo, its folds, narrowing and sparse tree, its evil state and mark, shrunk table columns and inline images. Two panes on one buffer therefore show the same folds, and a fold made in one shows in the other. Closing a pane leaves its buffers open; closing a buffer (=C-x k=) takes it out of every pane, which falls back to the buffer it showed before.

New Window (=C-x 5 2=, =⌥⌘N=, File ▸ New Window) opens a window of panes alone, without the sidebar or search, on the buffer the focused pane shows, as a second Emacs frame. Commands act on the pane with the focus whichever window it is in; Quick Open, the palette and search open from the main window and show their result in the focused pane. Closing the window closes its panes and leaves the buffers open.

* The modeline

The line under the editor shows, from the left:

| Item                       | Shown when                         | What it shows                                                     |
|----------------------------+------------------------------------+-------------------------------------------------------------------|
| Evil state                 | Doom preset                        | =NORMAL=, =INSERT=, =VISUAL=, =V-LINE= or =V-BLOCK=, on a coloured tag |
| Unsaved dot                | the buffer has unsaved edits       | a small dot                                                       |
| Outline path               | the caret is under a heading       | the headings containing the caret, outermost first, as =Projects › House › Roof= |
| Selection counts           | text is selected                   | lines, words and characters in the selection, as =count-words-region= |
| Line and column            | always                             | =LINE:COLUMN= of the caret (the end of the selection)             |
| Word count                 | always                             | words in the whole file, as =count-words=; click for the characters and reading time of the file and the selection |
| Encoding notes             | the file differs from UTF-8 with LF | =Read-only=, =BOM= and =CRLF=, in orange                         |
| Git branch                 | the file is in a Git repository    | the checked-out branch, or the first 7 characters of the commit when detached |

Lines count from 1. Columns count from 0, as Emacs's =column-number-mode= does: a tab advances to the next multiple of 8, and wide characters such as CJK count as two columns. Hover over an item for a description.

The word count follows edits after a pause. Reading time is at 230 words a minute, rounded up. The Git branch is read from the repository's =HEAD= file without running =git=, and checked again every 5 seconds; worktrees and submodules are followed.

The running clock shows in the toolbar; see [[file:06-dates-and-clocking.org][Dates and clocking]]. The evil states are covered in [[file:03-keys.org][Keys and commands]].

* The echo area

The line under the modeline is the echo area, as Emacs's minibuffer. It shows:

- *Messages* from commands, such as =Stored: …= or =Not an org file=. A message stays until the next key or click. View ▸ Messages lists the last 100.
- *A pending key prefix*. After =C-c= it shows =C-c-=. If you pause for about 0.6 seconds, a grid of the keys that can follow appears, each with the command it would run at the caret, or =+prefix= for a further prefix, as =which-key= shows them. =C-g= cancels the prefix and shows =Quit=. A sequence that isn't bound shows, for example, =C-c z is undefined=, and does nothing; in the Doom preset this includes sequences after =SPC=.
- *Prompts*, when a command asks a question.

** Prompts

A prompt shows its question and a text field, which takes the keyboard.

- Type an answer and press =Return=.
- When the prompt has choices (buffers, refile targets, tags), they list above the field, filtered as you type: characters match in order, and the best match is listed first and highlighted. The count at the right of the field shows the highlighted choice and the number of matches. =↑= and =↓= (or =C-p= and =C-n=) move the highlight, and =Tab= completes the field to the highlighted choice. =Return= accepts the highlighted choice when the prompt requires one of its choices or the highlight was moved, and the typed text otherwise. Clicking a choice accepts it.
- Prompts that take several values, such as tags separated by colons, complete only the part after the last separator.
- =Escape= cancels the prompt; the command reports =Quit=.

Date prompts also show a date picker, and =S-<left>=, =S-<right>=, =S-<up>= and =S-<down>= move the date by a day or a week; see [[file:06-dates-and-clocking.org][Dates and clocking]]. TODO keywords and tags with fast-selection keys show a key menu instead of a text field; see [[file:05-todos-and-tags.org][TODOs and tags]].

When a prompt closes, the keyboard goes back to the editor.

The Agenda and Board windows and the column view sheet ask their questions in the same prompt, at the bottom of the window or sheet.

* Completion

Complete at Point (=completion-at-point=) completes the word before the caret from what Org knows at that position.

| Preset | Key                                                      |
|--------+----------------------------------------------------------|
| Emacs  | =C-M-i=                                                  |
| Doom   | =C-SPC= or =C-@= in insert state                         |
| Mac    | =⌥⎋= (Option-Escape) while Option is Meta; =⌃Space= stays with macOS, which switches input sources with it |

With one candidate, it is inserted. With several, a list opens under the caret, showing up to 16 rows. Nothing is selected until you pick a row.

| Key                         | In the list                                                                |
|-----------------------------+----------------------------------------------------------------------------|
| =C-n=, =<down>=, =C-j=      | Next candidate; past the last one the selection goes back to what you typed |
| =C-p=, =<up>=, =C-k=        | Previous candidate                                                         |
| =TAB=                       | Insert the selected candidate; with none selected, insert the part all candidates share |
| =RET=                       | Insert the selected candidate; with none selected, close the list and insert a newline |
| =ESC=                       | Close the list; the key then does what it otherwise would                  |
| =C-g=                       | Close the list                                                             |

The list follows what you type and closes when nothing matches.

** Opening by itself

The list can open by itself, as corfu's =corfu-auto= does: after you type at least two characters and pause for 0.4 seconds, when the position offers something. With the Doom keys it does, as Doom's corfu does; with the Emacs and Mac keys it doesn't. Settings ▸ Editing ▸ Completion (=completion-auto=, =completion-auto-delay= and =completion-auto-prefix= in =config.toml=) changes all three for any keys; see [[file:13-configuration.org][Configuration]]. With the Doom keys it opens only in insert state.

** Matching

Candidates start with what you typed, sorted; this is Emacs's default (=completion-styles= with =basic= and =partial-completion=). With fuzzy matching (=completion-style = "fuzzy"=), a candidate matches when it has the letters you typed in order, anywhere, as the command palette matches, and the best matches come first: letters at the start of a word and runs of letters next to each other count most, then shorter candidates. Candidates in the case you typed come first when there are any, so =#+ti= lists =title:= rather than =TITLE:=. The Doom keys match fuzzily by default, as Doom's corfu does with orderless; the Emacs and Mac keys match prefixes. =TAB= inserts the part the candidates share only when it starts with what you typed.

** From your folders

Some positions offer what is in your other files too. The file's own candidates show at once and the rest join the list when the index answers, which doesn't hold up typing.

| Where                                        | Candidates                                                     | Inserted |
|----------------------------------------------+----------------------------------------------------------------+----------|
| After =[[id:=                                | Heading titles in every folder, and files with an =ID=; a title that several have shows its file's name | =[[id:ID][Title]]=, through =]]= after the caret |
| After =[[denote:=                            | Denote's notes, by title                                       | =[[denote:IDENTIFIER][Title]]= |
| After =:NAME: = in a property drawer         | The values the =NAME_ALL= property or =#+PROPERTY: NAME_ALL= allows at the caret, then the values headings give =NAME= in this file and in every folder, most used first | The value |

A heading chosen after =[[id:= that has no =ID= gets one first, in this file or in its own, as =org-id-get-create= adds it, so the link always points at an =ID=. If the heading's file changed so that the heading isn't where the index last saw it, nothing is added and the echo area says so.

** Words

Expand Word (=dabbrev-expand=) completes the word before the caret from words that start with it, ignoring case: in the file, those before the caret nearest first, then those after it nearest first; then in the other open files; then in your folders through the index. Each word is offered once. The case follows what you typed: =he= expands to =hello= from =Hello=, =HE= to =HELLO=, and a word with capitals inside, such as =fooBar=, keeps its own case when you typed its start as it is. Pressing the key again right away replaces the word with the next one; past the last, what you typed comes back and the echo area says =No further dynamic expansion for `he' found=.

| Preset | Expand Word | Complete Word                                                    |
|--------+-------------+------------------------------------------------------------------|
| Emacs  | =M-/=       | =C-M-/=                                                          |
| Doom   | —           | =C-n= in insert state (first chosen), =C-p= (last chosen), as Doom's =+corfu/dabbrev-or-next= |
| Mac    | =F5= (=fn-F5= on keyboards whose top row controls the Mac) | — |

Complete Word lists the same words in the completion list instead, with one chosen. Word characters are Org's: letters, digits and =$=, =%=, ='=, =&=, =*=, =+=, =-=, =/=, ~=~, =\=, =_=, =|= and =~=, so =fo= expands to =fo-y= or =fo/v= but not into =fo.z=. The list that opens by itself offers words only where Org offers nothing, and only with Settings ▸ Editing ▸ Completion ▸ The list offers words from open files and folders (=completion-words=).

What is completed, by position:

| Where                                        | Candidates                                                     |
|----------------------------------------------+----------------------------------------------------------------|
| =#+= at the start of a line                  | keyword names (=TITLE=, =STARTUP=, =OPTIONS=, …), in upper and lower case |
| After =#+STARTUP:=                           | startup options                                                |
| After =#+OPTIONS:=                           | export options                                                 |
| After =#+DATE:=                              | today's date as a timestamp                                    |
| After =#+EXCLUDE_TAGS:=, =#+SELECT_TAGS:=, =#+LANGUAGE:=, =#+PRIORITIES:= | the usual values                     |
| =<= and a letter at the start of a line      | structure templates (=<s= for a src block and so on); see [[file:11-code-blocks.org][Code blocks]] |
| After =#+BEGIN_SRC=                          | languages, then header arguments                               |
| After =#+BEGIN: clocktable=                  | clock table options                                            |
| After =[[=                                   | link types and the file's link abbreviations                   |
| After =[[*=                                  | heading titles in the file                                     |
| After =\=                                    | entity names                                                   |
| After =:= at the end of a heading            | tags: those in =#+TAGS=, or else tags used in the file and across your folders |
| After the stars of an empty heading          | TODO keywords                                                  |
| =:= at the start of a line in a property drawer | property names the entry doesn't have yet                   |
| =:= at the start of a line elsewhere         | drawer names                                                   |

Where none of these offers anything, the triggers of your snippets that match the text before the caret are offered, each with its description and marked =snippet=; choosing one expands it (see [[*Snippets][Snippets]]). Elsewhere, Complete at Point reports =No match=. Completion is for org files only.

* Snippets

A snippet is text you insert by typing its trigger and pressing =TAB=, as with yasnippet in Emacs. Snippets are defined in =snippets.toml= in the configuration folder; orgstar ships none. See [[file:13-configuration.org][Configuration]] for the file.

#+BEGIN_SRC toml
[[snippet]]
trigger = "meet"
description = "Meeting notes"
body = """
,* Meeting with ${1:someone} %U
- $0
"""
#+END_SRC

** Expanding

Type the trigger and press =TAB=. The trigger is the text before the caret back to a blank, or a shorter part of it that starts after a character other than a letter, digit or =_=: =(meet= expands =meet=. =TAB= expands a trigger only where it has no other meaning:

| Preset | Where =TAB= keeps its own meaning                                                                    |
|--------+------------------------------------------------------------------------------------------------------|
| Emacs  | Headings and the first or last line of a drawer or block (=org-cycle=), tables (next field)           |
| Mac    | The same as Emacs                                                                                    |
| Doom   | Normal and visual state (=org-cycle=); in insert state, headings (demote), list items (indent) and tables (next field) |

Your own =TAB= bindings in =keymap.toml= come first in the same way. Where =TAB= means something else, expand with Insert Snippet…, the completion list, or a key you bind to =org.snippet.expand= (Expand Snippet).

A snippet that asks questions (=%^{…}= in its body) asks them in the echo area first, one after another; =Escape= cancels and inserts nothing.

** Fields

After expanding, the caret is in the first field, with its default text selected, so typing replaces it. The field has a band behind it, and the other fields and mirrors a fainter grey one.

| Key      | While a snippet's fields are filled in                                        |
|----------+-------------------------------------------------------------------------------|
| =TAB=    | Next field; after the last, the caret goes to =$0= (or the end) and the snippet is done |
| =S-TAB=  | Previous field                                                                |
| =Escape= | The snippet is done; the caret stays. In the Doom preset, insert state ends as well. |

A field used twice (=$1= … =$1=) is mirrored: typing in the field changes every copy. Moving the caret out of the snippet, or an edit outside it, also ends it. Next Snippet Field (=org.snippet.next-field=) and Previous Snippet Field (=org.snippet.previous-field=) are the same as =TAB= and =S-TAB=, for binding to other keys.

** Insert Snippet…

Insert Snippet… (in the command palette) lists the snippets by description and trigger, and expands the one you choose at the caret. With text selected, the snippet replaces it, and =%i= in the body inserts it: a snippet with body =#+begin_quote\n%i$0\n#+end_quote= wraps the selection in a quote block.

Each snippet is also a command, =org.snippet:= and its trigger, such as =org.snippet:meet=, for a key in =keymap.toml=.

** Templates for new files

A snippet with =file = true= in =snippets.toml= is a template for a new file. File ▸ New File from Template… (or the command palette) asks for the template, the folder (that of the shown file to start with) and a name, as New File… does. The file is created empty and opens with the template expanded in it, its prompts asked and its fields ready to fill in.

* Electric pairs

Typing an opening bracket inserts its closing partner, as =electric-pair-mode= does. The pairs are =()=, =[]=, ={}=, =<>= and a pair of double quotes.

- Typing a closing character in front of the same closer moves over it instead of inserting another, skipping whitespace before it.
- =DEL= between an empty pair deletes both.
- =RET= between a pair opens a blank line between them.
- With text selected, typing an opening or closing character, or a double quote, wraps the selection.
- No pair is inserted where it would leave the brackets unbalanced (=electric-pair-preserve-balance=).

Electric pairs are on by default and work in org files only. Set =electric-pair-mode = false= in =config.toml= to turn them off. Plain Emacs has them off; Doom pairs with smartparens.

* Spell checking

Spell checking is off by default. Turn it on for the current buffer with View ▸ Check Spelling While Typing (also in the palette; =SPC t s= in Doom normal state); the echo area says whether it is now on or off. To have it on in every file, turn on Settings ▸ Editing ▸ Check spelling while typing, or set =spell-check = true= in =config.toml=.

Misspelt words are underlined, using the macOS spelling dictionary. In org files, orgstar doesn't mark words where spell-fu skips them: code, verbatim, links, timestamps, tags, TODO keywords, priorities, list bullets, checkboxes, keywords and affiliated keywords, planning and clock lines, property drawers, the first and last lines of drawers and blocks, the whole of src, example, export and comment blocks, LaTeX, entities, macros, targets, footnote references, citations, table formulas and fixed-width lines.

orgstar never corrects spelling on its own; automatic spelling correction, text replacement and smart quotes and dashes are off.

On iOS, spell checking follows =spell-check= in the synced =config.toml=, and is off by default. It leaves out the same text as on the Mac: misspelt words get a dotted red underline, and selecting one, or tapping it to show the edit menu, offers guesses and Learn Spelling. The word being typed is checked once the caret leaves it.

* Wrapping and filling

Long lines wrap at the edge of the editor by default. View ▸ Truncate Long Lines (=toggle-truncate-lines=) switches the current buffer to long lines that run off the right edge, with a horizontal scroll bar, and back. The echo area says which is now in effect.

| Preset | Key                          |
|--------+------------------------------|
| Emacs  | =C-x x t=                    |
| Doom   | =SPC t w= in normal state    |
| Mac    | menu or palette only         |

To truncate lines in every file, turn on Settings ▸ Editing ▸ "Long lines run off the edge instead of wrapping", or set =org-startup-truncated = true= in =config.toml=. The default is to wrap, as Doom does; Emacs's own default is to truncate.

The spaces that align a heading's tags (see [[file:05-todos-and-tags.org][TODOs and tags]]) never wrap. When the heading fits the line as written, it shows as written. When only the spaces don't fit, the tags show at the right edge; when the title and tags don't fit on one line, one space separates them. A line can't break between a title's last word and its tags, so at the largest text sizes, when the two together are wider than the line, the tags break. The reader on iPhone and iPad puts the tags on a line of their own instead. The file keeps its spaces.

Wrapping is display only. To rewrap the text of a paragraph, use Org ▸ Fill Paragraph (=org-fill-paragraph=), which breaks the paragraph's lines at the fill column: =M-q= in the Emacs preset and in every Doom state, =⌃⌘P= in the Mac preset. With a selection, it fills every paragraph the selection touches. In Doom's normal and visual states, =gq= and =gw= with a motion fill the paragraphs in the lines it covers (=gqq= and =gww= for the current lines); =gq= leaves the caret on the last line, =gw= where it was. Unlike Fill Paragraph, =gq= and =gw= keep extra spaces between words and at the ends of lines, as Doom does. See [[file:03-keys.org][Keys and commands]]. The fill column is Settings ▸ Editing ▸ "Fill Paragraph wraps lines at column N" (80 by default, 40 to 200), or =fill-column= in =config.toml=.

=auto-fill-mode= breaks lines as you type: typing a space past the fill column breaks the line at the last space before the column, as often as it takes, and the new line starts with the line's fill prefix, as =org-auto-fill-function= has it: a list item's text lines up under the item, a comment line starts with =#=, and headings, tables and code aren't broken. Turn it on for every file with =auto-fill-mode = true= in =config.toml=, or for the current buffer with View ▸ Auto Fill (=auto-fill-mode=, in the palette too); the echo area says =Auto-Fill mode enabled in current buffer= or =disabled=. Only a typed space fills, not =RET=.

The View menu shows a check mark next to each toggle that is on.

| Show Line Numbers             | View ▸ Show Line Numbers      | =⇧⌘L=                                           | off     | =display-line-numbers-type=      | every buffer   |
| Auto fill                     | View ▸ Auto Fill                | palette                                       | off     | =auto-fill-mode=                 | current buffer |

Toggles that apply to the current buffer last until it closes; the =config.toml= setting decides how each file starts. Changing those settings, and =org-startup-indented= and =org-hide-leading-stars=, affects files opened afterwards, not buffers already open.

** Line numbers

Line numbers show in a margin left of the text, as =display-line-numbers-mode= shows them: one number per line of the file, so wrapped lines are numbered once and folded lines are skipped. The caret's line number is brighter. Line numbers are off by default, as in Emacs.

View ▸ Line Numbers chooses how they count, as =display-line-numbers-type= does in =config.toml=:

| View ▸ Line Numbers | =display-line-numbers-type= | Numbers                                                                           |
|---------------------+------------------------------+-----------------------------------------------------------------------------------|
| Absolute            | =true=                       | The line's number in the file.                                                    |
| Relative            | ="relative"=                 | How many lines of the file away from the caret's line.                            |
| Visual              | ="visual"=                   | How many lines on the screen away from the caret's, counting each wrapped line.   |

In the relative and visual kinds the caret's line shows its own number, as =display-line-numbers-current-absolute= does. =display-line-numbers-type = false= turns the numbers off. The iOS editor has no line numbers.

* Themes

The editor's font, size, line spacing and heading sizes are in Settings ▸ Appearance. Settings ▸ Appearance ▸ Theme chooses a built-in theme for the light appearance and one for the dark: Default, Solarized Light, Gruvbox Light, Modus Operandi, Catppuccin Latte, Tomorrow or Paper; and Default, Solarized Dark, Gruvbox Dark, Modus Vivendi, Catppuccin Mocha, Nord, Dracula, Tokyo Night or doom-one. They are =light-theme= and =dark-theme= under =[theme]= in =config.toml=. Colours set in =config.toml=, under =[theme]= for both appearances, =[theme.light]= and =[theme.dark]= for one and =[theme.todo]= for TODO keywords, apply on top, as do those of a theme file named by =theme-file=. Copy to Config Folder writes the two chosen themes, every colour, into =my-theme.toml= and makes it the theme file, to start a theme of your own. Show Default Theme opens =default-theme.toml=, which lists every colour with its default value. Changes apply while orgstar runs. See [[file:13-configuration.org][Configuration]].

The iOS editor uses the same theme and display settings, read from the synced =config.toml=; see [[file:14-ios.org][iPhone and iPad]].

* Undo

Each buffer has its own undo history, kept while other buffers show.

| Action | Menu        | Mac     | Emacs preset              | Doom (normal state) |
|--------+-------------+---------+---------------------------+---------------------|
| Undo   | Edit ▸ Undo | =⌘Z=    | =⌘Z=, =C-/=, =C-_=, =C-x u= | =u=                 |
| Redo   | Edit ▸ Redo | =⇧⌘Z=   | =⇧⌘Z=                     | =C-r=               |

A command's whole change undoes in one step, separately from the typing around it. Restoring a recovery version and resolving a Syncthing conflict copy can be undone too.

The undo history is cleared when the buffer reloads or merges changes from disk, and when you take the disk version or merge with markers to settle a conflict; see [[file:01-files-and-folders.org][Files, folders and buffers]]. The Emacs preset has no redo key other than =⇧⌘Z=, and undo is linear, not Emacs's undo tree.

* Finding text in a file

=C-s= and =C-r= in the Emacs preset search as you type (=isearch-forward=, =isearch-backward=): the echo area shows =I-search:= and what you have typed, the next match is selected as each character goes in, and the other matches are highlighted. While searching:

| Key           | What it does                                                                                       |
|---------------+----------------------------------------------------------------------------------------------------|
| characters    | Add to the search string.                                                                          |
| =C-s=, =C-r=  | The next or previous match; with nothing typed yet, the last search again. After =Failing I-search=, the search wraps around the file (=Wrapped I-search=). |
| =DEL=         | Undo the last key: a character, or a move to another match.                                        |
| =RET=         | Stop, with the caret after the match (before it going backward).                                   |
| =C-g=         | With a failing search, take off the part that fails; otherwise stop and go back to where the search began. |
| other keys    | Stop where the search is, then run as usual.                                                       |

A space matches any run of spaces and tabs, and an upper-case letter makes the search case-sensitive, as Emacs's defaults have it. =C-M-s= and =C-M-r= search with a regular expression (=isearch-forward-regexp=); patterns are ICU regular expressions. Folded text opens around a match. In Doom, =/= and =?= search the same way with a regular expression, the echo area showing =/= or =?= and the pattern; =RET= ends it as Vim's search does, so =n= and =N= repeat it, and =Esc= or =C-g= go back. On iOS, =C-s= and =C-r= work with a hardware keyboard, and Incremental Search is in Commands; typing on the on-screen keyboard adds to the search. iOS doesn't highlight the other matches.

Edit ▸ Find opens the find bar above the text.

| Menu item                         | Shortcut | Emacs preset      | Doom                  |
|-----------------------------------+----------+-------------------+-----------------------|
| Edit ▸ Find ▸ Find…               | =⌘F=     |                   | =SPC s s=             |
| Edit ▸ Find ▸ Find and Replace…   | =⌥⌘F=    | =M-%=             |                       |
| Edit ▸ Find ▸ Find Next           | =⌘G=     |                   |                       |
| Edit ▸ Find ▸ Find Previous       | =⇧⌘G=    |                   |                       |
| Edit ▸ Find ▸ Use Selection for Find | =⌘E=  |                   |                       |

In Doom, =:s/PATTERN/REPLACEMENT/= and =:%s/…/…/= with the =g= and =i= flags substitute with regular expressions on the current line or in the whole file.

To search all your files, use the toolbar's search field; see [[file:01-files-and-folders.org][Files, folders and buffers]].

* Replacing in many files

Edit ▸ Find ▸ Replace in Files… (=⌥⇧⌘F=, or Replace in Files… in the command palette) replaces text in every file of one folder or of all your folders. Fill in Find and Replace with, choose the folder under In, and press Find. Selected text on one line starts as the search.

- *Plain text or regular expression.* With Regular expression on, the pattern is an ICU regular expression, as in the find bar and Doom's =:s=; =^= and =$= match at the start and end of each line. In the replacement, =\1= or =$1= is the first group, =\&= or =$0= the whole match, =\\= a backslash and =\$= a dollar sign. Plain text replaces literally.
- *Case.* As Emacs's defaults have it: with Ignore case when the search is lower case on (=case-fold-search=), a search with no upper-case letters matches any case, and one with an upper-case letter matches case exactly (a letter after a backslash in a regular expression doesn't count). With Keep each match's case on as well (=case-replace=), the replacement follows each match: =foo= replaced with =bar= turns =Foo= into =Bar= and =FOO= into =BAR=, as =query-replace= does.

The list shows every match by file and line, the matched text struck through and the replacement after it. Untick a match, or a file's box to leave out the whole file, then press Replace. While the search runs, a bar shows how many files are done; Stop ends it and keeps what it found.

What is searched:

- Org files (=.org=, =.org_archive=) and plain text (=.txt=, =.md=, =.markdown=) in the folder. Encrypted files (=.gpg=) are left out, and so are the encrypted entries in org files: the =-----BEGIN PGP MESSAGE-----= to =-----END PGP MESSAGE-----= text under a heading with the =crypt= tag (=org-crypt-tag-matcher=), its own or inherited. The tagged heading's own line is searched.
- An open file as it is in its buffer, unsaved changes included.

How each file changes:

- An open file changes in its buffer, as one edit: Edit ▸ Undo in that buffer takes back the whole replacement in that file. It is saved as any edit is, at once with automatic saving, else when you save.
- A file that isn't open is written at once through the same save path as a buffer, so a file changed on disk meanwhile is merged or reported as a conflict. Before it is written, its text is kept in recovery, as =Before a change across files=; there is no undo for it, but File ▸ Recovery Versions… on that file shows the old text and restores it (the restore can be undone).
- A file that changed after the search is left alone, and the echo area says so; search again.

The echo area then says how many files changed. Org ▸ TODO and Tags has Rename Tag… and Rename TODO Keyword…, which work the same way but change only tags or keywords; see [[file:05-todos-and-tags.org][TODOs and tags]].

* Lint File

File ▸ Lint File (=app.lint=, also in the command palette) checks the open Org file for mistakes, as =M-x org-lint= does, and lists them in a panel under the editor: the line, the severity, the problem and the checker that found it. Choosing a row moves the caret to that line. The list follows the file: after an edit it is checked again once you pause typing. Running Lint File again checks at once; the close button hides the panel. Nothing in the file is changed.

The severity is org-lint's trust in the checker. An error is almost certainly a mistake; a warning may be intended, such as a timestamp written without its day name. Messages are org-lint's own, in English.

* Accessibility

The editor works with VoiceOver. VoiceOver reads the text as it is shown rather than as stored: hidden link brackets and targets, hidden emphasis markers and hidden stars are skipped, entities are read as the characters drawn for them, and narrowed table columns are read as drawn. Folded text is still read, so the whole file is available. Lines, the caret position and the selection are reported in terms of the shown text.

Other parts of the window are labelled: tabs in the tab bar are buttons, with the current one marked selected, and each close button names its buffer and says whether it is unsaved; the outline pane's divider is an adjustable Outline width; the modeline's unsaved dot reads "Unsaved changes", and the Doom state tag reads, for example, "Normal state".

The editor keeps the system's keyboard navigation and text editing; the presets only add bindings. See [[file:03-keys.org][Keys and commands]].
