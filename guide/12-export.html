Exporting a file

Export works on the file in the current editor, using its text as it is now, saved or not. It applies to Org files only; in any other file the command says "Not an org file". Source blocks are never run during export. Results already in the file are exported as they are; see Code blocks.

The keys follow Emacs's export dispatcher (org-export-dispatch). C-c C-e on its own is only a prefix: pause after it and the key hints list the formats. The SPC m e keys work in normal state; the C-c C-e keys work in every Doom state. The Mac preset has no keys for the single formats; its ⇧⌘E opens the export dialog.

All sixteen commands are in File ▸ Export and in the command palette. They write the export beside the Org file, with the same name and the format's extension: .html, .md, .pdf, .docx, .rtf, .tex, .odt, .txt or .ics (.html for reveal.js). The two agenda-file commands are the exceptions; see iCalendar export. #+EXPORT_FILE_NAME: names it instead, as in Org: relative to the Org file's folder (or absolute, or starting with ~), with its extension replaced by the format's, so #+EXPORT_FILE_NAME: out/report writes out/report.html. A file already there is replaced. The message area shows "Exported to name", or "Exported the subtree to name", "Exported the body to name" or "Exported the subtree's body to name" when the export was not the whole file as a whole document.

The fourteen commands that export the current file export the whole file as a whole document, unless the file is set otherwise. Two commands set it, as C-s and C-b do in Org's dispatcher:

Both are in the command palette, and the message area says what is now on. The choice is kept for the file, and it is the same one the export dialog shows as Scope and Body only, so setting it in the dialog sets it for the commands too. With subtree export on and the caret before the first heading, a command says "Not in a subtree" and writes nothing. With body-only export on, a command for PDF, Word, RTF, plain text, ODT, iCalendar or reveal.js says "This format has no body-only export. Turn body-only export off for this file first." and writes nothing. The two agenda-file commands follow neither.

The Mac App Store version has the fifteen commands that don't need Emacs; File ▸ Export, the export dialog and the command palette leave out Export to PDF with Emacs, and a key bound to it runs Export to PDF. When the export file, or an #+INCLUDE: or #+SETUPFILE:, is outside your folders, orgstar first asks for access to its folder; for the export file, Save Elsewhere… instead picks another place. See Install.

The export dialog

Export… in the command palette, or ⇧⌘E in the Mac preset, opens a dialog. The Emacs and Doom presets have no key for it; bind app.export-dialog in keymap.toml if you want one (see Keys and commands). The dialog has:

  • Format: HTML, Markdown, PDF, Word, Rich Text (RTF), Plain text, PDF via LaTeX (Emacs), ODT, LaTeX, Plain text, ASCII, iCalendar or reveal.js slides. The App Store version lists LaTeX, Plain text, ASCII and reveal.js slides last.
  • Scope: the whole file, or the subtree at the caret (Org's C-s in the dispatcher). A subtree is exported as a document of its own: its heading is the title, its text the body, and its child headings move up a level. iCalendar is the exception: there the subtree's heading is an entry like any other. The file's #+ keywords still apply, and the heading's EXPORT_TITLE, EXPORT_AUTHOR, EXPORT_DATE, EXPORT_EMAIL, EXPORT_OPTIONS, EXPORT_SELECT_TAGS, EXPORT_EXCLUDE_TAGS, EXPORT_HTML_HEAD and EXPORT_HTML_HEAD_EXTRA properties override them. Its planning line and property drawer are left out. The choice is available when the caret is under a heading.
  • Body only: leave out the title and the page around the text (Org's C-b). HTML is then the table of contents, the text and the footnotes, without <html>, <head> or the title; Markdown has no title heading; ASCII has no title block or table of contents. Not available for PDF, Word, RTF, plain text, ODT, iCalendar and reveal.js slides.
  • Destination: where #+EXPORT_FILE_NAME: says, or the subtree's EXPORT_FILE_NAME property for a subtree, else beside the Org file. Choose… picks another place and name. Changing the format changes the extension.
  • Margins, Font and Page numbers, for PDF: see PDF export.
  • Open after export: opens the file in its default app when the export finishes.

The dialog keeps the format, scope, body-only and Open after export settings for each file, by the file's path, in orgstar's preferences; nothing is written to the Org file, and a renamed or moved file starts again. They are saved when you click Export. A file exported for the first time starts with the format and Open after export setting last used, the whole file, and body only off. When the kept scope is the subtree and the caret is before the first heading, the dialog exports the whole file. The destination is not kept. The PDF settings are config.toml settings, and apply to every PDF export.

On iOS

The Export menu offers HTML, Markdown, PDF, Word, Rich Text (RTF), Plain Text, ODT, iCalendar, LaTeX, Plain Text (ASCII) and reveal.js, and Copy as Rich Text. It is under More in the editor, and in the toolbar in the reader. Choosing one opens the share sheet with the exported file, named after the Org file or its #+EXPORT_FILE_NAME:. Send it to another app, or use Save to Files to keep it. The export is the same as on the Mac, except that LaTeX, ODT and ASCII have no author unless the file has #+AUTHOR:. PDF through LaTeX is not available on iOS.

Body Only in the Export menu leaves out the title and the page around the text, as in the Mac's export dialog, and is kept for each file. While it is on, PDF, Word, Rich Text (RTF), Plain Text, ODT, iCalendar and reveal.js say "This format has no body-only export. Turn body-only export off for this file first." Turn Body-Only Export On or Off, in Commands or on C-c C-e C-b with a hardware keyboard, changes the same setting. Export Subtree…, in the editor's Export menu, lists the formats for the subtree at the caret, and follows Body Only too. There is no subtree setting on iOS: the menu's formats always export the whole file.

Print… in the Export menu prints the file; see Printing. The Export menu also has Export Agenda Files to iCalendar and Combine Agenda Files into iCalendar (see iCalendar export). Export to HTML and Open, in Commands or on C-c C-e h o with a hardware keyboard, shows the HTML export in Quick Look, with the file's images in the page; nothing is written beside the Org file; it follows Body Only. Copy as Rich Text is in Commands too.

HTML export

orgstar writes a complete HTML page: a small built-in stylesheet that follows the system's light or dark appearance, the title, an author and date line, the table of contents, then the document. It does not use Emacs, and its output is close to, but not the same as, ox-html.

Which headings are exported

  • A heading tagged with one of #+EXCLUDE_TAGS (noexport by default) is left out, with everything under it.
  • A heading whose title starts with COMMENT is left out.
  • A heading tagged ARCHIVE is exported as the heading alone, without its contents.
  • If any heading has one of #+SELECT_TAGS (export by default), only those headings, their ancestors and everything under them are exported.

Each heading gets an id for links: its CUSTOM_ID property, or a slug made from its title. Headings are one level down from Org's: a top-level heading is an <h2>, since the title is the <h1>.

The page head

Each #+HTML_HEAD: and #+HTML_HEAD_EXTRA: line goes into the page's <head> as written, in order. Use them for stylesheets and scripts:

#+HTML_HEAD: <link rel="stylesheet" href="notes.css">

The built-in stylesheet is always included first. Other #+HTML_… keywords are not used.

Math

LaTeX fragments (\(…\), \[…\], $…$, $$…$$) and LaTeX environments are left in the page for MathJax. When the page has any, orgstar adds MathJax 3 from cdn.jsdelivr.net, so the page needs a network connection to show math. PDF export uses a copy of MathJax that comes with orgstar instead, so math in a PDF needs no network connection. Entities such as \alpha become their characters.

Includes

#+INCLUDE: inserts another file before export, as org-export-expand-include-keyword does. Paths are relative to the Org file.

A file that cannot be read is replaced by an empty line. In a file included as Org from another folder, relative file: links are rewritten relative to the Org file, as Org does: [[file:pic.png]] in sub/part.org becomes [[file:sub/pic.png]]. A link written without file:, such as [[./pic.png]], comes back as [[sub/pic.png]], which Org then reads as a link to a heading.

Macros

{{{name(arguments)}}} is replaced before export (org-macro-replace-all).

{{{keyword(NAME)}}}The value of #+NAME:.

Footnotes

Footnote references, named or inline ([fn:: text]), become numbered superscript links. The notes are collected in a Footnotes section at the end, numbered in the order they are first referenced, each with a link back. A reference without a definition is exported as written.

Tables

An Org table becomes an HTML <table>. If it has rules, the rows before the first rule are the header (<thead>) and the rest the body. #+CAPTION: gives the table a caption. #+TBLFM: lines are not exported.

A table.el table (one drawn with +, - and |) becomes a table with each cell's colspan and rowspan, and the lines in a cell joined with line breaks. If its drawing is not a well-formed table, it is exported as preformatted text.

Images and links

A link to an image file without a description becomes an <img>. The image types are png, jpg, jpeg, gif, svg, webp, bmp, tif, tiff and avif. #+ATTR_HTML: before the paragraph adds attributes (:width 300 :alt "Map"); without an :alt, the file name is used.

An attachment: link is exported as a file: link to the file in its entry's attachment folder, with its full path, as Org's org-attach-expand-links does; when the entry has no attachment folder, to that name in the Org file's folder. An attached image therefore shows as an image.

An image paragraph with #+CAPTION: or #+ATTR_HTML: becomes a <figure>; a caption is numbered "Figure 1:", "Figure 2:" and so on.

Links to .org files point to the .html file of the same name. Links to headings ([[*Heading]]), to CUSTOM_ID targets and to radio targets point to the heading's or target's id on the page. id: links point to # and the ID. Other links are written as they are.

Source blocks and their results

A source block is exported as <pre><code class"language-LANG">=, with the code escaped and its common indentation removed. Code in a language the editor highlights is colored as the editor colors it: each token is a <span> with the class Emacs's htmlize gives its face (org-keyword, org-string, org-comment, org-function-name, org-type, org-constant, org-property-name, org-variable-name), and the page's stylesheet colors them with the theme's syntax- colors, light and dark. Other languages are exported plain; the language- class lets a script or stylesheet in #+HTML_HEAD highlight them. Noweb references are shown as written. Code references are covered in Links: labels come off the lines, -n and +n number them, and [[(name)]] links to the labelled line.

The block's :exports header argument decides what appears. orgstar resolves it as running the block would: from the #+begin_src line, #+HEADER: lines, header-args properties and #+PROPERTY: lines (see Code blocks). Without one, it is results for dot, plantuml, ditaa, gnuplot, latex and lilypond blocks, as their Org defaults set it, and code for other languages.

:exportsExported
codeThe code.
resultsThe block's existing #+RESULTS:.
bothThe code, then the results.
noneNothing.

A #+CALL: line exports its existing results, never the call itself; :exports code or none on the call, or in the header-args properties where the call is, exports nothing. An inline src_ block has :exports results by default: the {{{results(…)}}} after it is exported and its code is not. With :exports code the code is exported in <code> and the results are not; with both, both. An inline call_ never appears itself, and the {{{results(…)}}} after it is always exported, whatever :exports says, as in Org.

reveal.js export

Export to reveal.js writes a slide deck for reveal.js, as Emacs's org-re-reveal package writes one (org-re-reveal-export-to-html), without Emacs, on the Mac and iOS. It writes a .html file, like HTML export, so the two replace each other unless #+EXPORT_FILE_NAME: tells them apart. Like PDF export, it needs orgstar+.

The deck is one file that works without a network connection: reveal.js 6.0.2, its stylesheet, the theme and the plugins come with orgstar and are put in the page, and so are the images the file links to and the slides' background images. Open it in a browser and share it as it is. With #+REVEAL_ROOT:, the deck links to reveal.js there instead, as org-re-reveal does, and images stay links: #+REVEAL_ROOT: https://cdn.jsdelivr.net/npm/reveal.js@6.0.2 uses a CDN, and a relative path a copy of reveal.js beside the deck. The files are read from reveal.js 6's dist folder (dist/reveal.js, dist/theme/black.css, dist/plugin/notes.js).

The slides:

  • A title slide first, with the title, #+SUBTITLE:, the author and the date (#+OPTIONS: author:nil and the rest leave them out).
  • A table of contents slide, as for HTML export; #+OPTIONS: toc:nil leaves it out, as most decks do. Section numbers are as for HTML export; num:nil leaves them out.
  • A slide for each heading down to H (3 unless #+OPTIONS: H:n says otherwise). First-level headings go across; their children go down from them, as reveal.js's vertical slides. #+REVEAL_HLEVEL: 2 puts second-level headings across too. Deeper headings are part of their slide, as HTML export writes them.
  • Text before the first heading, other than keywords, on a slide of its own after the title.
  • The footnotes on a last slide.

Inside a slide, everything is as HTML export writes it: lists, tables, colored code, images, links, math (MathJax, put in the page when reveal.js is), and #+BEGIN_EXPORT html and @@html:…@@ with their reveal forms. Headings tagged noexport and COMMENT headings are left out.

A heading's properties set its slide: REVEAL_BACKGROUND (a color, an image or a URL), REVEAL_BACKGROUND_SIZE, REVEAL_BACKGROUND_POSITION, REVEAL_BACKGROUND_REPEAT, REVEAL_BACKGROUND_TRANS, REVEAL_BACKGROUND_OPACITY, REVEAL_BACKGROUND_IFRAME, REVEAL_BACKGROUND_VIDEO, REVEAL_DATA_TRANSITION, REVEAL_DATA_STATE, HTML_CONTAINER_CLASS (its class) and REVEAL_EXTRA_ATTR (attributes as written).

Code keeps the editor theme's colors: the dark ones on a dark reveal.js theme (black, league, night, moon, blood, dracula, black-contrast), the light ones on the others.

On the Mac, Export to reveal.js (C-c C-e v v in the Emacs preset and Doom) and Export to reveal.js and Open (C-c C-e v b) are in File ▸ Export and the command palette, and the export dialog has reveal.js slides. On iOS, reveal.js is in the Export menu. Publishing writes decks with publishing-function = "org-re-reveal-publish-to-reveal".

Differences from org-re-reveal:

  • Without #+REVEAL_ROOT: the deck has reveal.js in it, where org-re-reveal links to ./reveal.js (or puts it in the page with reveal_single_file:t).
  • The files linked under #+REVEAL_ROOT: are reveal.js 6's (dist/plugin/notes.js), not reveal.js 4's (plugin/notes/notes.js).
  • The default plugins are notes, search and zoom; org-re-reveal's list also has markdown.
  • Slide ids are slide- and the heading's id as HTML export makes it (slide-introduction), not slide-org… ids that change with each export. Links to headings go to their slides.
  • Headings below H are headings, as in orgstar's HTML export, not list items.
  • Not read: #+REVEAL_EXTRA_JS:, #+REVEAL_SLIDE_HEADER: and #+REVEAL_SLIDE_FOOTER:, #+REVEAL_INIT_SCRIPT:, #+REVEAL_HIGHLIGHT_CSS:, #+REVEAL_MULTIPLEX_…, #+REVEAL_TOC_SLIDE_…, :code_attribs and other #+ATTR_REVEAL attributes than :frag and :frag_idx, and org-re-reveal's customizable variables.

Presenting

Present shows the file one heading at a time, full screen, as org-present and org-tree-slide show it in Emacs. Each slide is a heading's line, without its stars and tags, and its text, in the editor's theme at a size that fills the screen; its children are the slides after it. A title slide comes first when the file has #+TITLE:, #+AUTHOR: or #+DATE:, or text before the first heading. Planning lines, drawers, keywords and comments don't show; image links on lines of their own show as images; #+BEGIN_NOTES blocks are the slide's notes. Headings tagged noexport and COMMENT headings are left out, with their children. A slide too long for the screen scrolls. Present needs no orgstar+, and nothing is written.

On the Mac, View ▸ Present (⌃⌘P), also in the command palette, opens the slides in a full-screen window at the heading the caret is in.

KeyDoes
→, ↓, Space, Page Down, ReturnNext slide
←, ↑, Delete, Page UpPrevious slide
Home, EndFirst and last slide
EscapeLeave, as Done does

On iOS, Present is in the editor's Commands, starting at the caret's heading, and in the reader's, starting at the beginning. Tap the right two thirds of the screen or swipe left for the next slide, tap the left third or swipe right for the previous one, and tap Done to leave. With a hardware keyboard the keys above work too.

On an iPad with an external display and Stage Manager off, the slide shows on the display, and the iPad shows the next slide, the current slide's notes, the slide number, Previous and Next. With Stage Manager on, the display is an extended desktop and shows windows, not the slide.

PDF export

Export to PDF makes the HTML export into a PDF, laid out and split into pages by the system's web engine as printing does. It needs neither Emacs nor TeX, and works on iOS. The PDF has what the HTML export has: the title, the byline, the table of contents, colored code, tables, images and math (MathJax, which comes with orgstar and needs no network connection). For the page:

  • Colors are always the light ones, whatever the system's appearance.
  • Pages are US Letter where that is the usual size and A4 elsewhere; on the Mac, the paper size set for printing.
  • Code blocks, tables, figures and quotes are kept on one page when they fit, and a heading is not left at the bottom of a page.
  • Margins are 50 points on every side (pdf-margin under [orgstar] in config.toml; Margins in the Export dialog).
  • The text is in the export's own font, or the family pdf-font names (Font in the dialog). Code stays monospaced.
  • Each page's number is centred in its bottom margin (pdf-page-numbers; Page numbers in the dialog). The numbers are annotations on the pages, so the table of contents and other links keep working.

For typeset output with LaTeX's classes and packages, use Export to PDF with Emacs instead (see Exporting through Emacs).

Printing

Printing makes the same pages as Export to PDF, with its margins, font and page numbers, and hands them to the system's print panel, which shows a preview and the printer's own choices. Pages that don't fit the paper chosen there are scaled down to fit. Like PDF export, printing a file needs orgstar+, since the print panel can save a PDF; printing the agenda doesn't (see Agenda).

CommandPrints
Print…The whole file.
Print Subtree…The subtree at the caret, as a document of its own, as the export dialog's Scope exports it. "Not in a subtree" before the first heading.
Print Selection…The selected text, under the file's title and with its #+ keywords. "No text is selected" without a selection.

On the Mac the three are in the File menu and the command palette; Print… is ⌥⌘P, since ⌘P is Quick Open. File ▸ Page Setup… sets the paper size and orientation the pages are laid out for. Body Only and the file's subtree export setting don't apply to printing.

On iOS, Print… is in the Export menu and prints the whole file; Export Subtree… has Print… for the subtree; all three commands are in Commands, where Print Selection… is greyed without a selection. The pages are US Letter or A4, as for PDF export, and the system's print sheet scales them to the paper.

The text printed is the editor's, saved or not, as for export. An entry encrypted with crypt prints as its encrypted message unless it has been decrypted in the file (Decrypt Entry in File…); one only opened with Decrypt Entry… stays encrypted in the print. See Outlines.

LaTeX export

Export to LaTeX writes the .tex file that Emacs's org-latex-export-to-latex writes under emacs -Q (Org 9.8.7), without Emacs, on the Mac and iOS. It has the same preamble, sectioning, lists, tables, verbatim source blocks, figures, footnotes, links and escaping. Two things differ: the \label keys are made from the document, so they stay the same between exports, where Emacs picks new random ones each time; and \author is the name of the Mac's user account, which is what user-full-name usually is, unless the file has #+AUTHOR:.

Word, RTF and plain text

Export to Word, Export to RTF and Export to Plain Text make the HTML export into a document of that kind, as the system reads HTML: headings, emphasis, links, colored keywords and code, lists, and tables. Word files (.docx) are written by orgstar itself, so tables come through as Word tables; RTF keeps them too on the Mac. On iOS, where the system's HTML reader keeps no tables, Word's tables are made from the HTML export's tables, with header cells bold and the cells' text without its styles; RTF and plain text there have the cells' text but no table. Plain text is the same text without its styles: list bullets and table cells are kept, separated by tabs. Fonts are Helvetica Neue for text and Menlo for code, and the colors are the light ones.

In Word files, the title has Word's Title style and headings have its Heading 1 to Heading 6 styles, so Word's navigation pane, outline view and contents fields find them. Images from file: links come through as pictures, as wide as their pixels at 96 to the inch, scaled to #+ATTR_HTML: :width when it is set, and no wider than the page. PNG, JPEG and GIF go in as they are; other formats the system can read, such as HEIC, WebP and TIFF, go in as PNG. SVG and images at web addresses are left out. RTF and plain text have no images.

For Org's own ASCII layout, with underlined headings and drawn tables, use Export to Plain Text (ASCII); see ASCII export.

Copying as rich text

Copy as Rich Text (the command palette on the Mac, the Export menu on iOS) puts the selection, or the whole file when nothing is selected, on the clipboard as HTML, RTF and plain text. Paste it into Mail, Pages, Word or a web form to get the formatted text. On iOS it copies the whole file.

ODT export

Export to ODT writes an OpenDocument text file (.odt) for LibreOffice, Pages or Word. orgstar writes it itself, on the Mac and on iOS, the way Emacs's ox-odt does under emacs -Q: the same headings, paragraphs, lists, tables, links, notes and images, with ox-odt's style names, so a template that restyles ox-odt's output restyles this one too.

  • The title, subtitle (#+SUBTITLE:), author and date come first, then the table of contents and the text. On the Mac, without #+AUTHOR:, the author is your account's full name, as user-full-name is in Emacs. Without #+TITLE: there is no title.
  • Headings are numbered by the word processor, to the depth num gives (num:t numbers every level). Headings deeper than H become list items. #+TOC: headlines puts a table of contents where it is; local limits it to the section, counts the depth from there and leaves out the title.
  • Footnotes are the word processor's own notes, numbered as ox-odt numbers them: those referred to in the text first, then those referred to only from other notes. A note referred to again shows its number.
  • Tables keep their header rows, alignment cookies, column groups and cell borders. A table inside a list item ends the list, sits indented below it, and the list carries on after it, as in ox-odt.
  • Images from file: links (PNG, JPEG, GIF and SVG) are put inside the file. Their size is their pixels at 96 to the inch, or #+ATTR_ODT: :width, :length (the height) or :scale, and no more than 17 by 20 cm. A caption or #+NAME: numbers figures, tables and source blocks, and a link to the name shows the number.
  • LaTeX fragments and environments are kept as written, in code style, as ox-odt does without a MathML converter. Source blocks are not colored; a language Emacs has no mode for gets ox-odt's plain code style.
  • Without :exports, every source block exports its code, dot, plantuml, ditaa, gnuplot, latex and lilypond included: emacs -Q loads no Babel library to give them results, so their #+RESULTS: are left out, with or without :file. With :exports results or both, the #+RESULTS: already in the file are exported as they are. A line of only spaces in a source block is exported empty, unless -i keeps the indentation.
  • Of the #+OPTIONS, \n, f, |, e and d (t or nil) are read, along with those every export reads.
  • #+ODT: lines, #+BEGIN_EXPORT odt blocks and @@odt:...@@ snippets go in as they are.
  • The styles (styles.xml) are orgstar's own: A4 pages with 2 cm margins. #+ODT_STYLES_FILE: is not read.

The export stops with a message, instead of writing something different from ox-odt, for: a link that leads nowhere, an image file that can't be read, inline tasks, table templates (#+ATTR_ODT: :style), a link without a description to a <<target>> or to a code line that isn't numbered, an inline source block exported as code, a table in a quote or other block inside a list, an annotation in a dated document, #+TOC: with :target, and these #+OPTIONS at other than their default: p, c, prop, broken-links, :, *, stat, tasks, <, arch, email, ', tex other than t or nil, and d with a list of drawers. ODT export is always the whole document: the export dialog's Body only doesn't apply.

ASCII export

Export to Plain Text (ASCII) writes the .txt file that Emacs's org-ascii-export-to-ascii writes under emacs -Q (Org 9.8.7), without Emacs, on the Mac and iOS: a centered title block, a table of contents, numbered headings underlined by level, paragraphs filled to 72 columns, links listed at the end of their section, and footnotes at the end. It uses Org's default ascii charset (org-ascii-charset), so bullets, rules and table borders are plain ASCII characters. Without #+AUTHOR:, the author on the Mac is your account's full name, as user-full-name is in Emacs.

#+TITLE, #+SUBTITLE, #+AUTHOR, #+DATE, #+LANGUAGE, #+TOC: headlines, #+ASCII: lines, #+BEGIN_EXPORT ascii blocks, @@ascii:...@@ snippets, #+ATTR_ASCII: :width on horizontal rules, and the center, justifyleft and justifyright blocks work as in Emacs, as do the tags and COMMENT that leave headings out (see Which headings are exported). Body-only and subtree export are in the export dialog. In a subtree export, the heading's EXPORT_TITLE, EXPORT_SUBTITLE, EXPORT_AUTHOR, EXPORT_DATE, EXPORT_LANGUAGE, EXPORT_OPTIONS, EXPORT_SELECT_TAGS and EXPORT_EXCLUDE_TAGS properties replace the file's keywords. Leading tabs in a source block become spaces, as in Emacs.

On iOS the share sheet stops and the message shows at the bottom of the screen. Publishing to plain text stops with the file's name in the message. In the download version, when Emacs is installed, such a file is exported by Emacs instead (see Exporting through Emacs).

Markdown export

Markdown export writes GitHub-flavored Markdown:

  • #+TITLE: becomes a top # heading. Org headings are one level down: * is ##. TODO keywords stay in the heading text, and tags are shown as inline code. Priority cookies are left out unless #+OPTIONS has pri:t.
  • Source blocks become fenced code blocks with the language; example blocks, =: = lines and table.el tables become fenced blocks without one.
  • Tables become pipe tables. A rule after the first row makes it the header; otherwise the header row is empty.
  • Checkboxes become task-list items (- [x], - [ ]).
  • Footnotes become [^1] references with the notes at the end.
  • Quotes become > blocks. Verse lines end with two spaces.
  • Images become ![](path). Links to .org files, with or without file:, point to the .md file of the same name; a search option after :: is dropped.
  • #+begin_export blocks for markdown, md or html, and @@html:…@@ snippets, are copied as they are.
  • Underline, subscripts and superscripts are written as HTML tags.
  • :exports is handled as in HTML export.
  • Citations are handled as in HTML export.

As in HTML export, #+INCLUDE: lines are expanded and macros replaced first, and #+EXCLUDE_TAGS, #+SELECT_TAGS, COMMENT headings and ARCHIVE tags decide which headings are exported (see Which headings are exported). Of the #+OPTIONS, Markdown export reads todo, pri, tags, ^ and title; the others do not apply. It writes no author or date.

iCalendar export

iCalendar export writes the .ics file org-icalendar-export-to-ics writes, for calendar apps to read or subscribe to. Each heading can give:

  • a VEVENT for its DEADLINE and one for its SCHEDULED date, as org-icalendar-use-deadline and org-icalendar-use-scheduled say. Their summaries start with =DL: = and =S: =;
  • a VEVENT for each other timestamp in its title and text, active ones only unless #+OPTIONS has <:t or <:inactive;
  • a VTODO for a task, as org-icalendar-include-todo says. Its DTSTART is the scheduled date (with todo-start in org-icalendar-use-scheduled), its DUE the deadline (with todo-due in org-icalendar-use-deadline); without a scheduled date, a deadline with a + repeater starts its warning period before it. STATUS is NEEDS-ACTION or COMPLETED, and PRIORITY maps A to 1, B to 5 and C to 9.

The summary is the heading's title, or its SUMMARY property. The description is the heading's text as Org's ASCII export writes it, filled to 70 columns, or its DESCRIPTION property; LOCATION, CLASS, TIMEZONE and APPT_WARNTIME (an alarm, minutes before a timed event) are read too. The calendar is named after the file, its description is #+TITLE:, and its owner #+AUTHOR: or your full name. Lines longer than 75 characters are folded and lines end in CRLF, as RFC 5545 asks.

Export Agenda Files to iCalendar writes an .ics beside each agenda file (see The agenda). Combine Agenda Files into iCalendar writes all their entries to one calendar named OrgMode at org-icalendar-combined-agenda-file. On iOS, the Export menu's iCalendar shares the current file's calendar, Export Agenda Files to iCalendar writes beside each agenda file as on the Mac, and Combine Agenda Files into iCalendar opens the share sheet with the combined calendar, named as org-icalendar-combined-agenda-file is; from Commands it opens in Quick Look, whose share button saves or sends it.

Differences from Org: diary sexps (%%(…) lines and <%%(…)> timestamps) are left out, as they need Emacs's icalendar.el. The other org-icalendar-* variables keep Org's defaults: alarms only from APPT_WARNTIME, categories (local-tags category), the whole body as the description, and local times. Descriptions of tables with column groups or alignment cookies, center blocks and links to targets can differ from Org's in layout.

Exporting through Emacs

On the Mac, PDF through LaTeX is done by Emacs, with org-latex-export-to-pdf, the function Emacs's dispatcher uses.

LaTeX and plain text go to Emacs (org-latex-export-to-latex, org-ascii-export-to-ascii) only for a file orgstar's own export can't write as Emacs would; see LaTeX export and ASCII export. The Mac App Store version doesn't run Emacs and has none of these exports.

orgstar runs emacs -Q --batch in the Org file's folder. It opens the file, replaces its contents with the editor's current text without saving, and calls the function. Emacs writes the result beside the file, as it would itself; with a destination chosen in the export dialog, orgstar then moves it there. The message area shows "Exporting with Emacs…" and then "Exported to name".

What you need:

  • Emacs, at ORGSTAR_EMACS or one of /opt/homebrew/bin/emacs, /usr/local/bin/emacs, /Applications/Emacs.app/Contents/MacOS/Emacs, /run/current-system/sw/bin/emacs or /usr/bin/emacs. Without it the export fails with "Emacs isn't installed, so this format can't be exported."
  • For PDF, a TeX installation that Emacs's LaTeX export can run. Emacs runs with your PATH plus /opt/homebrew/bin, /usr/local/bin, /Library/TeX/texbin, /usr/bin and /bin, the same as code blocks get, so latexmk and pdflatex from MacTeX or Homebrew are found when orgstar was opened from the Dock.

Things to know:

  • -Q means Emacs does not load your init file. Your LaTeX classes, export settings and packages from it are not used; the export uses Org's defaults and what the file itself sets.
  • File-local variables are applied only when Emacs considers them safe.
  • org-export-use-babel is off, so no source blocks run.
  • An export that takes more than two minutes is stopped with "Emacs took too long to export."
  • Edit ▸ Cancel Running Task (⌘.) stops the export and shows "Export canceled". Starting another export or table recalculation in Emacs cancels the one that is running.
  • If Emacs fails, the message area shows the last line of its error output.

To use your own Emacs configuration, or formats orgstar does not list, export from Emacs itself; see Alongside Emacs.

Citations

HTML and Markdown export process citations as Org's basic citation processor does (oc-basic).

#+bibliography: refs.bib
#+cite_export: basic author-year

As shown in [cite:@smith2020], and again [cite/t:@smith2020; see @lee2019 p. 4].

#+print_bibliography:

Bibliography files

Each #+bibliography: line names one file, relative to the Org file, optionally in quotes. A file ending in .json is read as CSL-JSON; anything else is read as BibTeX, with @string abbreviations expanded and @comment and @preamble skipped. You can have several #+bibliography: lines; for a key in more than one file, the first file wins. The files of org-cite-global-bibliography (see Configuration) come after the file's own. Inserting and following citations are in Links.

#+cite_export:

#+cite_export: PROCESSOR [BIBLIOGRAPHY-STYLE [CITATION-STYLE]].

  • With no #+cite_export:, or with basic, citations are processed.
  • With any other processor, such as csl or biblatex, orgstar leaves citations as they are written.
  • The citation style, which may include a variant (text/bare), is the default for citations that do not name one.

Citation styles

A citation is [cite:…] or [cite/style:…] or [cite/style/variant:…], holding one or more @key references separated by ;. Each reference may have its own prefix and suffix, and the whole citation a common prefix and suffix.

StyleOutput
default (none given)(Author, Year)

noauthor, na(Year)

note, ftA footnote holding the text form
numeric, nb(1), numbered by the cited works sorted by author; three or more in a row as 1-3

Works by the same author in the same year get a, b, … after the year. A key not found in any bibliography file shows as ?? and ????. Citations in the title are dropped.

For note citations, the blank before the citation is removed and punctuation right after it moves in front of the footnote mark, as org-cite-adjust-note does.

The bibliography

#+print_bibliography: is replaced by an entry for every cited work, sorted by author. The bibliography style from #+cite_export: sets the form:

Bibliography styleEntry
defaultAuthor (Year). /Title/, Publisher.
plainSurnames. Title, Publisher, Year.
numeric[1] Author, /Title/, Publisher, Year.

The publisher part comes from the publisher, journal, institution or school field. Without #+print_bibliography: no bibliography is written.

What export does not do

  • There is no asynchronous export.
  • Source blocks are not run, and noweb references are not expanded.
