Link syntax

orgstar reads links the way org-element-link-parser does. There are three forms.

FormExampleNotes
Bracket link[[https://orgmode.org][Org website]]Any link type. The description after ][ is optional.
Angle link<https://orgmode.org>For http, https, mailto, file, id, doi, ftp, news, shell, elisp, info, help and attachment.
Plain linkhttps://orgmode.orgOnly https://, http://, mailto: and file: are recognized in running text.

Inside a bracket link, a target that starts with /, ~, ./ or ../ is a file link. A target in parentheses, (name), is a coderef. One that starts with # is a custom ID. Anything without a known type: prefix is a search for text in the current file (a "fuzzy" link). A link may run over a line break; the break and surrounding blanks read as one space.

Backslashes before brackets are escaped as in org-link-escape: when orgstar writes a link it doubles backslashes that come before a bracket or the end, and it reads them back the same way.

How links display

With View ▸ Show Markup off (the default, ⇧⌘M toggles it), a link with a description shows only its description, and its brackets and target are hidden. This is org-link-descriptive. The full text appears on the line that holds the caret, so you can edit it. With Show Markup on, every link shows as written. The setting is show-markup under [orgstar] in the config file (see Configuration).

Links without a description show their target, with the brackets hidden in the same way. Radio targets (<<<words>>>) turn every other occurrence of those words in the file into a link, matched case-insensitively, as in Org.

Following links

org-open-at-point follows the link at the caret, shows the entry of a citation (see Citations below), or opens the agenda for a timestamp.

PresetKey
EmacsC-c C-o
Mac⌃⌘O
DoomC-c C-o in any state; RET in normal state follows a link before doing anything else
All⌘-click on the link; o at the start of a heading line when speed commands are on

A message in the echo area explains a link that can't be followed.

What each link type does

LinkExampleResult

doi[[doi:10.1000/182]]Opens https://doi.org/ followed by the DOI.
file (also file+sys:, file+emacs:)[[file:notes.org::*Ideas]]See File links below.

Heading[[*Weekly review]]Moves to the heading in this file with that title.
Text[[budget table]]Searches this file: a <<budget table>> target, then #+NAME: budget table, then a heading.
Coderef[[(ref)]]Moves to the label (ref:ref) in a src or example block; see Code references below.
Regexp[[/TODO.*soon/]]Shows a sparse tree of the regular expression's matches, as org-occur; iOS moves to the first match.

The text search follows org-link-search. A dedicated <<target>> matches its words case-insensitively, with any run of blanks between them. A heading matches when its title, with statistics cookies such as [2/5] and a leading COMMENT removed, has the same words as the link, ignoring case. A search that starts with * looks at headings only. A regular-expression search (/re/) shows a sparse tree of its matches on the Mac, as org-occur does, and moves to the first match on iOS.

Following a radio link moves to its <<<radio target>>>, matching the words without regard to case, as org-link--search-radio-target does. When the target is gone, the echo area shows No match for radio target: and the text.

File links

A relative path is resolved against the folder of the file that holds the link, as Org does; ~ is your home folder; an absolute path is used as written. Links between files in different sidebar folders work the same way, for example [[file:../work/projects.org]] or [[file:~/Documents/org/inbox.org]].

What happens depends on the file:

  • An .org or .org_archive file opens as a buffer in orgstar.
  • Another text file opens in orgstar as a plain buffer.
  • Anything else (images, PDFs, archives, media) is handed to macOS, which opens it in the default app for that type.

If the file doesn't exist, the echo area shows No file and the path.

After ::, a file link can carry a search option:

OptionExampleMoves to
A number[[file:log.txt::120]]Line 120.
*Title[[file:notes.org::*Ideas]]The heading with that title.
#custom-id[[file:notes.org::#setup]]The heading with that CUSTOM_ID.
Other text[[file:notes.org::budget]]A target, a #+NAME or a heading, as above.

Attachment links

An attachment: link names a file in the attachment folder of the entry that holds the link (see Outlines for the attachment commands). Relative folders are resolved against the folder of the file that holds the link:

  1. When the entry has a DIR property, or the older ATTACH_DIR, that folder.
  2. Otherwise, for an entry with an ID, the first of these folders that exists: org-attach-id-dir (data/) followed by the ID's first two characters, / and the rest of the ID; followed by its first six characters, / and the rest; __/, the ID's first character, / and the whole ID. When org-attach-id-dir is something else, the same folders under data/ are found too.

org-attach-use-inheritance decides whether DIR and ID may come from an ancestor.

When the folder does not exist, the path is relative to the file's own folder. The file then opens as a file: link would, and a search option after :: works the same way.

id links

id: links are resolved through the index, so the target heading must be in a file under one of your sidebar folders. An ID in the property drawer before a file's first heading names the file, as org-roam's file nodes do, and the link opens the file. A link to an ID that isn't indexed shows No heading has the ID followed by the ID.

denote links

denote: links name a Denote note by its identifier, as in [[denote:20261119T120000][A note]]. The note is the indexed file whose name has the identifier, at its start or after @@; an Org file comes before others with the same identifier, such as a PDF. A search after ::, such as ::#custom-id or ::*Heading, works as in a file: link. Backlinks list denote: links to a file, and to a heading when the link searches for it.

In Denote's Markdown and text notes, Open Link (or a ⌘-click on the Mac) follows [[denote:ID]] and [[denote:ID][Title]], and in Markdown also Denote's own [Title](denote:ID); other links there aren't followed. Backlinks list these notes too.

Emacs Lisp links

Following an elisp: link whose path starts with ( asks Execute (form) as Elisp? (yes, no, always), as org-link-elisp-confirm-function does. always trusts the link's form in this file, so the question isn't asked again until it changes. The echo area then shows (form) => value, or the error's message.

  • On the Mac with Emacs installed, the form runs in emacs -Q --batch in a copy of the file, with point at the caret, so Org functions see the file's text. Changes the form makes to the buffer or to files in Emacs's session are not kept.
  • On iOS, in the Mac App Store version, and on the Mac without Emacs, the form runs in orgstar's Emacs Lisp interpreter, with the functions listed under Lisp formulas in Tables. A form that uses anything else, or a variable it doesn't bind itself, such as fill-column, shows This link uses Emacs Lisp that runs only in Emacs.

A path that names a command, such as elisp:org-agenda, isn't run. The reader view on iOS doesn't run elisp: links; open the file in the editor.

Timestamps

C-c C-o (Mac ⌃⌘O) or ⌘-click on a timestamp opens the agenda on that day, as org-follow-timestamp-link does. On a date range such as <2026-10-05 Mon>--<2026-10-09 Fri>, the agenda shows the whole span. See Agenda.

Inserting and editing links

org-insert-link asks for a link and a description in the echo area.

PresetKey
EmacsC-c C-l
Mac⌘K
DoomSPC m l l, or C-c C-l

The first prompt reads Insert link:, or Insert link (default …): when you have stored links. It completes from:

  • your stored links, most recent first, and their descriptions;
  • the link abbreviations defined in the file (see Link abbreviations);
  • the link types attachment, id, eww, rmail, mhe, irc, info, gnus, docview, bibtex, bbdb, w3m, doi, file+sys, file+emacs, shell, news, mailto, https, http, ftp, shortdoc, help, file and elisp, each followed by :.

Pressing Return on an empty answer inserts the most recent stored link. Choosing a description inserts the link it belongs to. If you choose a bare type such as https:, a second prompt, Link (no completion support):, asks for the rest.

The next prompt, Description:, offers the stored link's description, or the selected text if you selected some before running the command. An empty description inserts a link without one. With text selected, the link replaces the selection.

When the caret is on an existing link, the same command edits it: the Link: prompt starts with the current target and Description: with the current description.

A stored link that you insert is removed from the stored list, as with org-link-keep-stored-after-insertion set to nil.

File paths in inserted links

When the inserted link is a file: link, orgstar rewrites it as org-link-make-string-for-buffer does:

  • A link to a heading or target in the file you are editing loses its file: part and keeps only the search, for example [[*Ideas]].
  • A path under the current file's folder becomes relative to it.
  • Any other path is written with ~ for your home folder.

Completion while typing

You can also type a link by hand. With the caret right after [[, completion at point offers attachment:, doi:, file:, http:, https:, id: and mailto:, plus the file's link abbreviations. After [[*, it offers the headings of the current file. After @ in a citation, it offers the keys of the file's bibliographies (see Citations). Completion at point is C-M-i in the Emacs preset and C-SPC in Doom's insert state; see The editor.

Storing links

org-store-link remembers a link to where the caret is, for a later Insert Link.

PresetKey
EmacsC-c l
Mac⌃⌘L
DoomSPC m l s or SPC n l

The stored link is a file: link to the current file, written with ~ for your home folder, followed by a search option chosen as Org does with org-link-context-for-files on:

  1. If the caret touches a <<target>> on its line, the link points at the target.
  2. Otherwise, if text is selected, the link searches for that text.
  3. Otherwise, if the caret is in an element with a #+NAME, the link uses the name.
  4. Otherwise, inside a heading's entry, the link uses #custom-id if the heading has a CUSTOM_ID property, and *Title if not. The title becomes the description.
  5. Before the first heading, the link searches for the text of the current line.

The echo area shows Stored: and the description or link. Storing the same link again moves it to the front of the list. Stored links last until you quit orgstar; they aren't saved between sessions, as in Emacs.

IDs

Org identifies headings across files with an ID property. Two commands manage it.

CommandOrg functionKeys
Org ▸ Create IDorg-id-get-createNo default key
Org ▸ Store ID Linkorg-id-get-create + org-id-store-linkDoom SPC m l i; no key in Emacs or Mac

Create ID gives the heading at the caret an ID property if it doesn't have one. The ID is a new UUID in lower case, for example 6a3c2f9e-…, as org-id-uuid makes them. Before the first heading, the property goes into the file-level property drawer.

Store ID Link does the same, then stores an id: link to the heading with its title as the description. Before the first heading, the description is the #+TITLE, or the file name. If the caret is on a target or named element inside the entry, the link carries that search, as id:…::search, which mirrors org-id-link-use-context.

CUSTOM_ID is a property you set yourself, with the property commands in Outlines. Link to it with [[#name]] in the same file or [[file:other.org::#name]] from another. Store Link uses it when the heading has one.

Targets and radio targets

<<target>> marks a place in the text that a link with the same words reaches: [[target]]. Store Link with the caret on a target stores a link to it.

<<<radio target>>> makes every other occurrence of its words in the file a link, matched case-insensitively and between non-word characters. Radio links are highlighted as links and exported as links to the target (see Export). Following one moves to the radio target.

Link abbreviations

A #+LINK: line defines an abbreviation, as org-link-abbrev-alist-local does:

#+LINK: gh https://github.com/%s
#+LINK: search https://duckduckgo.com/?q=%h
#+LINK: wiki https://en.wikipedia.org/wiki/

[[gh:orgmode/org-mode]]   → https://github.com/orgmode/org-mode
[[search:org tables]]     → https://duckduckgo.com/?q=org%20tables
[[wiki:Org-mode]]         → https://en.wikipedia.org/wiki/Org-mode

In the template, %s is replaced by the text after the colon, %h by the same text percent-encoded, and a template with neither has the text appended. Function templates (%(…)) are not supported. Abbreviations from a #+SETUPFILE count too. When a key is defined twice, the first definition wins.

The backlinks pane

View ▸ Show Backlinks shows a pane under the outline pane of an org file. It has two sections:

  • Links to the heading at the caret, named after that heading.
  • Links to This File.

Each row shows the linking heading, the line the link is on with links shown as they read and this one in bold, and the file name; a link in the text before a file's first heading is listed under the file's name. Click a row to open it. When nothing links to the file or the heading, the pane shrinks to one line, Links to This File None. The pane is shown by default, orgstar remembers whether it is shown, and it updates as you move the caret and edit.

The pane looks at every org file in your sidebar folders, including unsaved changes in open buffers. A link counts when following it would lead to the heading or the file:

  • id: links to the heading's ID, or to the file's own ID for the file section;
  • file: links and plain paths (./, ../, /, ~/) to the file, with no search option for the file section, or with ::*Title, ::#custom-id or ::Title for a heading;
  • within the same file, [[*Title]], [[#custom-id]] and [[Title]].

Links to targets, names and line numbers are not counted. A heading's links to itself are left out.

Nodes and daily notes

orgstar works with notes kept the org-roam way: headings and files with an ID are nodes, linked with id: links, and a daily note is a file a day. It reads them from the index, without org-roam's database.

CommandEmacsDoomWhat it does
Find Node…C-c n fSPC n r fAsks for a node by title or alias and opens it (org-roam-node-find).
Find Ref…—SPC n r FAsks for one of the nodes' refs and opens its node (org-roam-ref-find).
Insert Node Link…C-c n iSPC n r iAsks for a node and inserts [[id:…][Title]], with the alias as the description when an alias was chosen; with a selection, the selection is the description (org-roam-node-insert).
Show Node GraphC-c n gSPC n r gOpens the graph of nodes and their links; see The graph below.
Go to Today's, Yesterday's, Tomorrow's Daily NoteC-c n d d, y, tSPC n r d t, y, mOpens the day's note, making it if missing (org-roam-dailies-goto-today and the others).
Go to Daily Note for Date…C-c n d cSPC n r d dAsks for a date, then opens its note.
Capture to Today's Daily Note (and Yesterday's, Tomorrow's, for Date…)C-c n j, C-c n d n, C-c n d vSPC n r d n, T, Y, M, DFiles the entry template at the end of the day's note and opens it at %? (org-roam-dailies-capture-today and the others).
Next Daily Note, Previous Daily NoteC-c n d f, bSPC n r d f, bFrom a daily note, opens the next or previous one there is (org-roam-dailies-goto-next-note).

The keys are the ones org-roam's manual suggests for Emacs and Doom's. A file node's title is its #+TITLE, or its name. The node properties are read as org-roam 2.3 reads them:

  • ROAM_ALIASES: other titles for the node, separated by spaces, with quotes around one that has spaces ("Alias One" two). Each alias is listed in the chooser as a title of its own.
  • ROAM_REFS: links and citation keys the node stands for, such as https://example.com @key2020 [cite:@key2021]. Find Ref… lists them.
  • ROAM_EXCLUDE: with any value but nil, the heading or file isn't a node. It isn't inherited: the headings under an excluded one with an ID are still nodes.
  • Tags: a file node's are its #+FILETAGS; a heading's are its own and those it inherits. The chooser shows them after the title, as #tag, as Doom's chooser does, and typing a tag finds its nodes.

Names that repeat show their file's name. A [[roam:Title]] link opens the node with that title or alias, as org-roam-link-follow-link does.

A title that no node has opens the capture window with the [[roam-template]] templates from capture.toml, as org-roam-capture- does: choose one when there are several, answer its prompts, edit the text, and press Capture (⌘Return on the Mac) to make the node, or Cancel to make nothing. Find Node… then opens the node; Insert Node Link… links to it. Without templates, org-roam's default is used:

[[roam-template]]
key = "d"
name = "default"
type = "plain"                          # entry, item, checkitem, plain or table-line
template = "%?"
file = "%<%Y%m%d%H%M%S>-${slug}.org"    # in org-roam-directory
head = "#+title: ${title}\n"            # at the top of a new file

olp = "Projects/Active" files the text under that outline path, making the headings that are missing (file+head+olp). A new file starts with an ID property drawer and the head; a file that's there gets an ID when it has none, and is the node. ${title}, ${slug} and ${id} are the node's title, slug and ID; %<…> and the other escapes are org-capture's (see Capture), and immediate-finish, prepend and the other template properties apply. The slug is the title in lower case, accents dropped, with everything but letters and digits as one _, as org-roam-node-slugify makes it.

org-protocol's roam-ref opens the node whose ROAM_REFS has the ref, and otherwise makes one in the capture window with [[roam-ref-template]] (only the one keyed template when the link names one), with the ref in its ROAM_REFS. Without templates, org-roam's default makes ${slug}.org with #+title: ${title}; ${ref} and ${body} are the link's ref and body. roam-node opens the node with the node ID:

org-protocol://roam-ref?template=r&ref=https%3A%2F%2Fexample.com&title=Example
org-protocol://roam-node?node=5f0c1e2a-…

The graph. Show Node Graph, or Window ▸ Node Graph on the Mac and Commands on iOS, draws every node as a dot and every id: link between two nodes as a line. It is part of orgstar+.

  • A link belongs to the innermost heading with an ID around it, else to its file's node; a link written where there is no node, or to an ID no node has, isn't drawn. Several links between the same two nodes are one line.
  • A dot is larger the more links its node has. The node the caret is in is orange. Titles are drawn where they have room, the most-linked nodes first; zooming in shows more.
  • Drag to move the picture, pinch or use the buttons to zoom, and click or tap a node to open it.
  • Only the Open Note's Links keeps the node the caret is in and the nodes linked with it.
  • Unsaved text counts, as it does for Find Node….

Daily notes are in org-roam-dailies-directory (daily/) under org-roam-directory, which is the first sidebar folder unless set. A new note is named and started as org-roam's default daily template does it, with an ID like every new org-roam file:

,:PROPERTIES:
,:ID:       5f0c1e2a-…
,:END:
#+title: 2026-10-11

org-roam-dailies-file ("%<%Y-%m-%d>.org"), org-roam-dailies-head ("#+title: %<%Y-%m-%d>\n") and org-roam-dailies-entry ("* %?") change the file name, what a new note starts with, and what capturing adds; %<…> formats the note's date as format-time-string does. The entry is an org-capture template; its date escapes (%t, %U and the like) use the note's day. See Configuration.

For several daily templates, [[roam-dailies-template]] tables in capture.toml take the place of those three settings, as org-roam-dailies-capture-templates does. They have the keys of [[roam-template]]; type is entry unless set, and file is in the daily-notes folder. Capturing opens the capture window with them: choose one, edit the entry, and Capture files it in the day's note, making the note with the template's head when it's new. The go-to commands ask which template only when the templates name different files. Import from Emacs reads one (file+head NAME HEAD) template into the three settings, and several into tables.

Denote

With notes-package = "denote" in config.toml, the same commands follow Denote:

  • The graph draws the notes with a Denote identifier and their denote: links to each other.
  • Find Node… and Insert Node Link… list the Org, Markdown (.md) and text (.txt) files whose names have a Denote identifier, titled by their front matter's title, and Insert Node Link… inserts [[denote:…][Title]], or [Title](denote:…) in a Markdown note.

  • A title no note has makes a note in denote-directory (the first folder unless set), after the questions denote-prompts lists, in its order. The default is "title keywords"; the title is always the one typed.

    • keywords: separated by commas or spaces, offering the keywords in existing file names.
    • subdirectory: a folder under denote-directory (. for itself) to put the note in.
    • date: the note's date, read as org-read-date reads one; without a time, the time is now's.
    • template: a key of [denote-templates], whose text goes after the front matter.
    • signature: put in the name after ==, in lower case with = between words, and in a #+signature: line.

    file-type and identifier are not asked: a note is in the file type denote-file-type sets (Org unless set; see Markdown and text notes below), and the identifier is the date's, or the first second after it no file under denote-directory has. With the default prompts:

    #+title:      Field Notes
#+date:       [2026-11-19 Thu 12:00]
#+filetags:   :ideas:work:
#+identifier: 20261119T120000

    named 20261119T120000--field-notes__ideas_work.org: the title in lower case without punctuation, words joined by -; the keywords sorted, each one word, joined by _.

  • The daily-note commands work on denote-journal's entries: notes in denote-journal-directory (journal, under denote-directory) with the denote-journal-keyword (journal). With denote-journal-interval (daily), one entry lasts a day, a week (Monday to Sunday), a month or a year, and the entry for a date is the one whose identifier's date is in that stretch. denote-journal itself takes a date outside the current week, month or year as today; orgstar uses the date's own. A new entry is titled by denote-journal-title-format ("%A %-e %B %Y %H:%M"). Capturing adds org-roam-dailies-entry as for org-roam.
  • Store Link in a Denote note stores [[denote:ID][Title]], or denote:ID::#custom-id in an entry with a CUSTOM_ID, as Denote does with denote-org-store-link-to-heading nil.

denote-directory can hold several folders, separated by :. New notes go in the first; the subdirectory question offers all of them and their folders, and identifiers are kept unique across them.

Renaming

  • Rename Note… (denote-rename-file) asks the questions denote-prompts has among title, keywords, signature and date, each starting with the current value, then renames the file in its folder and rewrites its front matter. Empty answers remove a part. A file without an identifier gets one from its modification time; a file without front matter gets it added at the top.
  • Rename Note from Front Matter renames the open file from its #+title:, #+filetags: and #+signature:, keeping its identifier, as denote-rename-file-using-front-matter does. A missing line leaves that part out of the name. The keywords are sorted, and the front matter is rewritten from what was read: keywords sorted and in lower case, the signature as it is in the name, and an #+identifier: line added when there was none.
  • Rename Notes in Folder from Front Matter… does that for every Denote note in a folder of denote-directory, as denote-dired-rename-marked-files-using-front-matter does with them all marked.

Links keep working after a rename, as they use the identifier.

Markdown and text notes

Denote's markdown-yaml, markdown-toml and text file types are read and written with their own front matter. With denote-file-type = "markdown-yaml" in config.toml, a new note is 20261119T120000--field-notes__ideas_work.md and starts:

---
title:      "Field Notes"
date:       2026-11-19T12:00:00+01:00
tags:       ["ideas", "work"]
identifier: "20261119T120000"
---

markdown-toml writes the same lines between +++ lines, as title = "Field Notes" and so on. text makes a .txt note:

title:      Field Notes
date:       2026-11-19
tags:       ideas  work
identifier: 20261119T120000
---------------------------

A signature: line follows the identifier when the note has one. A .md file is YAML when it starts with --- and TOML when it starts with +++; one with neither takes denote-file-type when that is a Markdown type, else YAML.

In these notes:

  • Find Node…, Insert Node Link…, the graph and backlinks work as for Org notes; on the Mac the backlinks pane shows under the outline for them too. Insert Node Link… writes [Title](denote:ID) in Markdown and [[denote:ID][Title]] in text, as Denote's denote-md-link-format and denote-org-link-format do; [[denote:ID]] when there is no title.
  • Open Link follows denote: links (see denote links above).
  • Rename Note…, Rename Note from Front Matter and Rename Notes in Folder from Front Matter… rename them and rewrite their front matter in its own format: Markdown values in double quotes, keywords as ["a", "b"] in Markdown and separated by two spaces in text, the date as RFC 3339 (2026-11-19T12:00:00+01:00) in Markdown and 2026-11-19 in text. A line that is there keeps its key and spacing. A file without front matter gets it at the top.

Otherwise they are Markdown and text files as described in Files and folders: org's commands, Store Link, the sequence commands and denote-org's blocks aren't available in them. Capture templates with denote = true and denote-journal's entries are always Org notes, since they file org entries, as Denote's denote-org-capture does.

Query links

[[denote:query-contents:REGEXP]] and [[denote:query-filenames:REGEXP]] offer the notes whose text, or name, the Emacs regexp matches, ignoring case, and open the one chosen. In the iOS reader they list the matches.

Importing and limits

Import from Emacs reads denote-directory (a folder or a list), denote-file-type, denote-prompts, denote-templates, denote-silo-directories, denote-sequence-scheme, denote-journal-directory, denote-journal-keyword, denote-journal-interval and denote-journal-title-format. A link without a description shows an image when it points to a file ending in .png, .jpg, .jpeg, .gif, .svg, .webp, .tif, .tiff, .bmp, .heic or .avif (in any case), on a line of its own or in a line's text:

Pasting and dropping images

Paste (⌘V, or Edit ▸ Paste on iOS) with an image on the clipboard and no text runs yank-media, as in Emacs 29 and later: the image is saved as org-yank-image-save-method says and a link to it is inserted at the caret; with the caret on a heading's line, under the heading, after its planning line and drawers. M-x yank-media does the same on the Mac.

org-yank-image-save-methodWhere the image goesLink
attach (the default)The entry's attachment folder, as org-attach-attach puts it[[attachment:NAME]]
a folder, such as "images/"That folder, relative to the file's folder unless absolute; made if missing[[file:images/NAME]]

The name is Org's: clipboard- and the time, as in clipboard-20261011T232238.png; a second image in the same second gets -2. PNG, JPEG and GIF are saved as they are, and other image types as PNG. Before the first heading, attach gives the file a file-level ID, as Emacs does.

Files dropped on the editor on the Mac, or pasted after copying them in Finder, are handled as org-yank-dnd-method says: attach copies them into the entry's attachment folder (an image goes to the org-yank-image-save-method folder when that is a folder), file-link links to them where they are, open opens them, and ask, the default, asks which. An image dragged in without a file, such as one from a browser, is pasted as above. On iOS, dropped files are always attached, since what a drop hands over is a copy. Attach Photo or Video… and Take Photo… also insert their links at the caret.

Two things differ from Emacs, so that a pasted image shows at once: the link has no description (Org writes [[attachment:NAME][NAME]], which inline display skips), and it goes on a line of its own, breaking the line around the caret when it holds text.

Sizing

An image is drawn at its own width, up to the width of the text area. To set a width, put #+ATTR_ORG: :width with a number of points among the keywords above the link:

#+CAPTION: Network layout
#+ATTR_ORG: :width 300
[[file:images/network.png]]

The height follows the image's proportions. #+ATTR_HTML and other exporters' attributes don't affect the editor.

Showing images when a file opens

The config key org-startup-with-inline-images (default false) shows images in every file when it opens. In a file, #+STARTUP: inlineimages or #+STARTUP: noinlineimages overrides it.

org-protocol store-link

orgstar handles org-protocol://store-link URLs, in the new form org-protocol://store-link?url=…&title=… and the old form org-protocol://store-link:/URL/TITLE. The URL is added to your stored links with the title as its description, and is also copied to the clipboard. Insert it with Insert Link. Setting up a browser bookmarklet, and org-protocol://capture, are in Capture.

Citations

A citation, [cite:@key], names an entry of the bibliography files the file lists with #+bibliography: lines, or of those org-cite-global-bibliography lists for every file (see Configuration). The citation syntax and how citations export are in Export. A file ending in .json is read as CSL-JSON; anything else as BibTeX or BibLaTeX, with @string abbreviations expanded and the fields an entry lacks taken from the entry its crossref field names (whose title becomes the booktitle). Bibliography files are read in the background, and read again only when they change. In the Mac App Store version, a bibliography outside your sidebar folders asks for access to its folder the first time.

Inserting citations

Insert Citation… (Org ▸ Links and Footnotes on the Mac, Commands on iOS) is org-cite-insert with the basic processor.

PresetKey
EmacsC-c C-x @
Macnone; Org menu or palette
DoomSPC m @

What it does depends on where the caret is:

  • Outside a citation, it asks for an entry (Key:, each key with its authors, year and title), then a prefix, a suffix and a style (author, noauthor, nocite, note, numeric, text or nil), and inserts [cite/style:prefix @key suffix]. An empty answer leaves out the prefix, the suffix or the style.
  • On a citation's [cite/style part, it asks only for a style and puts it in place of the old one; an empty answer removes it.
  • On the citation's common prefix or before a reference's @, it adds the chosen key, with the prefix and suffix around it, before that reference; on a reference's suffix or the common suffix, after it. References are separated by ;.
  • Inside a key, the chosen key replaces it; the reference's prefix and suffix stay.

Without bibliography files, the echo area says No bibliography set. Where orgstar differs from Emacs:

  • It inserts one key at a time. Run it again inside the citation to add another; Emacs asks for keys until an empty answer.
  • It always asks for a style for a new citation; Emacs asks only after C-u. The prefix and suffix questions are orgstar's.
  • C-u doesn't delete the citation or reference at the caret.

Completing keys

Inside a citation, completion at point after @ offers the keys of the file's bibliographies, each with its authors, year and title.

Following citations

C-c C-o (Mac ⌃⌘O), ⌘-click, and RET in Doom's normal state show a citation's entry: its authors, year, title and where it was published. Its buttons open the files in the entry's file field, its DOI and its URL, and Show in Bibliography opens the bibliography file at the entry, which is what org-cite-basic-goto does in Emacs. On a reference the entry is that key's; elsewhere in a citation with several keys, you choose a key first. A key no bibliography has shows Cannot find citation key: and the key.

The file field may list several files, separated by ;. Each is a path or JabRef's and Zotero's description:path:type, relative to the bibliography's folder unless absolute.

Zotero

Better BibTeX for Zotero can keep a .bib file exported from your library up to date (Export Library, with Keep updated). List that file in #+bibliography: or org-cite-global-bibliography like any other; orgstar reads it again when Zotero rewrites it. [[zotero://select/items/@key]] links, with Better BibTeX's citation keys, open the item in Zotero on the Mac; on iOS the link is handed to the system, which opens the Zotero app if it is installed and handles the address.

On iOS

The iOS app follows links: tap a link in the reader. Org files open in the app, and web, mail and other files go to the system. The iOS editor shows inline images as the Mac does, and so does the reader, except in headings. In the editor, Store Link, Store ID Link, Insert Link… and Insert Citation… are in Commands, and on a hardware keyboard the Emacs keys run them; they work as described above, and stored links last until the app quits. Open Link in Commands shows the entry of the citation at the caret. The app reads only bibliography files in its folders. org-protocol://store-link links opened on the device are stored and copied too. Show Backlinks in Commands lists the same links as the Mac's backlinks pane, for the heading at the caret and the file. See iOS.

Code references

A label at the end of a line in a src or example block, (ref:name) by default, is a code reference, and [[(name)]] links to it. Following the link moves to the label. A block's -l "<<%s>>" switch changes the label's form for that block; %s is the name.

In export, the label is taken off the line. A block with -n numbers its lines from 1, or -n 10 from 10; +n goes on from the numbers of the blocks before it. -r leaves the label out of the exported line, and then the link shows the line's number instead of the name; -k with -n keeps the label while the link still shows the number. A link's description may contain %s for the name or number: [[(call)][line %s]]. In HTML, the line with the label is the link's target, coderef-name.

A regexp link, or a file:…::/regexp/ search, exports as its description, or its text when it has none.
